# The dispatcher — one list from two queues, and never a second proposal

**Date:** 2026-11-16 · **Component:** dispatch · **Door:** `bin/dispatch/dispatch.sh`

## What was wrong

Two queues filled every day and nobody read them in order. The mail desk knows which letters want an
answer; the durable wake queue holds the decisions that stopped a worker. Both were read by hand, or by
a door that only knew one of them, so a letter could be asked for twice, and a worker's question could
sit in a queue nobody drains.

Two doors proposing the same thing, with no shared key, is the fault this change exists to remove.

## What changed

**The door** — `bin/dispatch/dispatch.py` behind `bin/dispatch/dispatch.sh`. It reads Gná's desk
needs-you queue (`needs_you` and `unsure`, per declared account, over the desk or over the store the
desk reads, through Gná's own classifier) and the last 200 lines of `state/.wake-queue`. It keeps only
a `needs-decision` from the wake queue: a **`lock-ask` belongs to whoever holds the arm and is never
proposed** — measured on this seat, 106 lock-asks sat in a two-day queue, and not one is his to-do.

It writes proposals between two markers inside the **house-kept half** of
`hodd/life/personal/me/todo.md` and appends to `hodd/state/dispatch/runs.jsonl`. It never writes his
half, never sends mail, never spawns, never takes the arm.

Three laws, and each is a test:

1. **Idempotent by key** — `sha256(source|id)`. The to-do itself carries the key, so a duplicate is
   refused even if the ledger is deleted.
2. **The attempt cap is three** — a key that failed three times is terminal; the fourth attempt is
   refused, recorded once, and every later run is a no-op naming it.
3. **An unreadable input is an error** — exit 3, a `failed` run row, and the file named. Never `0`.

Plus `--dry-run` (writes nothing at all) and `--check` (inputs readable, ledger parses, markers whole,
state dir writable), both proved.

**The job** — `bin/time/nornir-job-dispatch.sh` runs the door, passes its exit code through, and carves
a rune only for a run that changed his list or failed (the ledger already holds every run, so the audit
trail is not a ten-minute heartbeat).

**The timer** — a `dispatch` row in `config/units.yaml` (mode `render`, every 10 minutes), rendered by
`bin/engine/units.sh`. There is no hand-written unit file.

## Proof

`bin/dispatch/tests/test_dispatch.py` — 51 assertions, wired as the gate
`bin/gates/checks.d/0500-dispatch.sh`. The four the errand asked for are the first four it prints:
unchanged input is a no-op; the same item never becomes two proposals (also with the ledger deleted);
the fourth attempt is refused; an unreadable input exits 3 and writes nothing.

Measured on the Allfather's seat the same day: `dispatch.sh --dry-run` read the live desk (road `desk`)
and found 3 needs-you rows in 48 hours, with 106 lock-asks correctly left to the arm.


## What is still owed

- **Wave B, the spending.** A proposal names its shape (`errand` or `line`); the arm spends it. This
  wave proposes and records, and deliberately does not spawn.
- **One proposal shelf, not two.** `bin/records/comms.py todo-matches` also proposes from the mail
  record. Until the two roads share a shelf, the dispatcher's "already on his list" guard is the only
  thing stopping a double line — it works, but two doors with two formats is drift.
