# Hvergelmir — the news app enters the tree, named by the law

**2026-11-05 · component: apps · `apps/hvergelmir/` · `apps/README.md`**

His word: *"make it to a separate app to ymir also. we can use it as a just news app. name it by the naming law. and thet it
in to the apps folder"*, after the audit of its own video (`52JX83rGPLc` / `OLqP8jxJ0Wc`) and the discovery that the repo is
ours (`zerwiz/pi-durable-news-agent`, MIT).

## What was done

- Vendored whole into **`apps/hvergelmir/`** (`.git` and `node_modules` excluded), with the upstream README kept as
  `UPSTREAM.md` and the MIT licence kept at `LICENSE`.
- **Named Hvergelmir** — the well from which every river runs — because an application is named for a **place**, and this one
  is many sources into one pool with only the carrying water leaving. (Hlidskjalf, Óðrerir, Sessrúmnir, Smíðja: the same shape
  of name.)
- **Registered** in `apps/README.md`, which is the registry per Rule 22.
- Its `jev` package, its hype/facts/signal vocabulary and its card catalogue are named in the README as the parts Ymir reuses
  — the client is framework-free and can be vendored; the UI is Vue 3.5 while Odrerir is React 19, so the **design** merges
  and the **components** do not (plan 200 §17).

## What it deliberately is not

- Not a second inbox: a story worth acting on becomes an item in the one list the operator already reads (`pending.sh`).
- Not a second login: it is reached behind the same gate, or run as a door, never as a parallel auth surface.
- Not a rewrite: vendored, so upstream can be pulled again — absorbing the app is the drift the smithy audit warns about.
