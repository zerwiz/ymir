# Bilskirnir keeps its hall in one home, not in a checkout

**2026-11-12 · component: apps · `apps/bilskirnir/scripts/data-home.sh` · `start.sh` · `setup.sh` · plan 275 S5**

## What was wrong

The hall kept its database, agents, engines, desk and `.env` under `apps/bilskirnir/` of whichever checkout ran it.
When the launcher moved to the pinned runtime, the icon opened a second, empty hall: the operator's agents and
conversations were still in the working tree's copy.

## What was done

`scripts/data-home.sh` links `data/` and `.env` to one home per user — `BILSKIRNIR_DATA_HOME`, else
`${XDG_DATA_HOME:-~/.local/share}/ymir/bilskirnir`. The first checkout to run moves its state there. A later checkout
that has its own copy sets it aside as `<name>.aside-<stamp>`, so nothing is deleted. `start.sh` and `setup.sh` run it
first. `.gitignore` ignores the links and the set-aside copies.

## Proof

`apps/bilskirnir/tests/data-home.sh` — 8 of 8: the first checkout donates its hall, a second checkout opens the same
hall and keeps its own copy aside, `--check` changes nothing, and a second run is a no-op.

## Owed on a machine that already has two halls

Run the door first in the checkout whose hall is the real one, while its server is stopped, so that hall becomes the
home. Then any other checkout links to it.

## Appended 2026-11-12 15:55 CET — the real hall is chosen by itself, and the first agent keeps the user's changes

- **No manual step.** With no home yet, the door looks at every Bilskirnir checkout on the machine (its own, the
  pinned runtime, the main tree) and the largest database — the real hall — donates its state, even when an empty
  checkout runs first. A hall under a running server is never taken; its own next start links it.
- **The first agent keeps what the user changed.** Her soul now takes the managed-block road every other agent takes
  (`house/house.py soul --existing`), so the user's own lines survive; her `config.yaml` is merged
  (`house.py merge`): the house's parts are refreshed, the user's model, tool servers, toolsets and settings are kept.
- **A fault of the hand that built it, recorded.** The first run of the new donor test was not fenced: it read the
  real pinned runtime as a candidate and moved that checkout's own, near-empty hall into its temp folder before its
  cleanup removed most of it. The operator's real hall was never touched; the pin's is regenerated by `setup.sh`. The
  test now points the pin, the main tree and HOME inside its temp folder.
- Proof: `apps/bilskirnir/tests/data-home.sh` 12 of 12; `apps/bilskirnir/tests/keeps-user-changes.sh` 5 of 5.
