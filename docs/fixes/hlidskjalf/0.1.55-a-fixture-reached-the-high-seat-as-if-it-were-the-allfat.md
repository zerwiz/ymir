## hlidskjalf · 0.1.55 · 2026-09-30 — a fixture reached the high seat as if it were the Allfather's diary

### Why
Found by the smoke test after #252 merged, and **caused by my own verification**: at 20:30 I ran
the reader by hand with `--fixture` and **no `--cache`**, so it wrote its 5 invented events into
the hoard's canonical rolling cache. The smoke then asked the gate API for the reckoning and got:

```json
{"as_of":"2026-09-30T17:30:37.299Z","state":"ok",
 "events":[{"id":"ev-all-day","title":"Invented All-Day Gathering", …}]}
```

The high seat was serving **fabricated meetings as real**, with a fresh timestamp and `state:"ok"`.
Two doors allowed it, and both were wrong in the same way:

1. **The reader would write a fixture to the canonical cache.** `--cache` is optional, so the
   canonical path was simply the default. A test seam and the production store were one flag apart.
2. **The gate route trusted freshness alone.** It checked `as_of` against the TTL and never asked
   **where** the answer came from — so `source: "fixture"` read exactly like a real Google read.

The plan's own law covers this: *unknown must never look like empty* — and worse, unknown must
never look like **real**.

### Fix
- **The reader refuses the canonical write.** A fixture may only ever write a cache the caller
  NAMED (`--cache <path>` or `MANAGANDR_CACHE`); otherwise it exits non-zero with the reason and
  the hoard cache is untouched. (While mending this I found and fixed a real bug in the same
  file: `--cache` was parsed into `args.cache` but read as `args.cache`, so the flag never
  reached the reader at all — the named-cache path could not have worked.)
- **The gate route surfaces `source` and refuses to call a fixture `ok`.** The answer now carries
  `source: 'google' | 'cache' | 'fixture' | 'unknown'`, and a fixture-sourced cache answers
  `state: "unknown"` with its source named — never `ok`, whatever its timestamp says.

### Verified — the three states are distinct, and the fixture cannot get there
```
no cache at all                 → {"as_of":null,"state":"absent","events":[]}
fixture-sourced cache           → {"as_of":"…","state":"unknown","source":"fixture","events":[…]}
MANAGANDR_CACHE=<named> + fixture → exit 0, written where it was told
--fixture with NO --cache       → exit 2, "refusing to write fixture data to the canonical cache …"
```
- The polluted cache is **removed from the hoard** (kept at `/tmp/polluted-cache-fixture.json`).
- `.agents/tests/managandr-reader.test.sh` → **all checks passed** (the new guard did not break
  the fixture's own path, which always named its cache).
- `apps/hlidskjalf` `npm run typecheck` → clean.
- Headless Chromium against the SPA: **0 console errors**, `/api/session` → `authed: true`, and
  the built bundle carries both `Mánagandr` and the `managandr` gate id.

### Standing
- `/api/calendar` answers **200 without a session** on loopback, like every other read route in
  this gate API (it is bound to 127.0.0.1 and the auth story is the session cookie + proxy). Not
  a new hole, but the brief's "401 without a session" is not what the code does — recorded so the
  next reader of that brief is not misled.
