## hlidskjalf · 0.2.0 · 2026-11-03 — Skirnir's answer line was a syntax error on main

### Why
Rule 43's English rewrite left an apostrophe unescaped inside a single-quoted string and a truncated closing tag in Skirnir.tsx line 266, so apps/hlidskjalf did not compile and the npm pretest gate failed on every PR and on main.

### Files
- `apps/hlidskjalf/src/gates/Skirnir.tsx`
### The fault

`apps/hlidskjalf/src/gates/Skirnir.tsx` line 266 read:

```
{answer || 'The answer appears here from Skírnir's existing knowledge and answer gate.'}</
```

Two faults in one line, both from a rewrite into English: an **apostrophe inside a single-quoted string**
(`Skírnir's` closes the string early), and a **closing tag cut in half** (`</` then `p>` on the next line).

`tsc --noEmit` therefore failed, `apps/hlidskjalf` did not build, and `bin/forge/npm/npm-pretest.sh` — which
builds every app before a pack — reported *"app-build failed — packing now would ship a tarball with no app
surfaces"*. That gate runs in CI on every PR, so **every branch and `main` itself showed a red `pr-pretest`**
for a one-line syntax error nobody could see from the summary.

### What changed

The line is one complete element again, with the apostrophe in a double-quoted string and the `</p>` closed:

```
{answer || "The answer appears here from Skírnir's existing knowledge and answer gate."}</p>
```

### What was proved

`npx tsc --noEmit` in `apps/hlidskjalf` → clean. `bash bin/forge/npm/npm-pretest.sh` → the app build leg passes
and the pretest verdict is PASS.

### Why it is recorded here

It is the third false red of one evening (the capability register, the per-clone merge driver, this). Each was
invisible in the check summary and each made good work look broken. A house that cannot trust a red will stop
reading them — which is exactly how a real fault ships.
