
### The fault

`bin/gates/guards/features-guard.sh` required `merge.regenerate.driver` in the **clone's git config** — a
setting `bin/records/weave-features.sh --install` seats by hand. A fresh clone has never run it, and CI clones
fresh every time. So the ward failed on **every** PR and on `main` itself, reporting *"the merge driver is not
seated"* on a machine where no merge ever happens.

The signature was unmistakable once looked at: the same ward passed locally and failed in CI, on a tree where
`weave-features.sh --check` said *current*.

### What changed

The driver is **declared** in `.gitattributes` (`FEATURES.md merge=regenerate`), which is tracked, so every
clone and CI carry the declaration. The guard now judges:

- the declaration (`git check-attr merge -- FEATURES.md` must be `regenerate`), and
- the presence of `bin/records/regenerate-on-merge.sh` in the tree;

and reports a missing per-clone config as a **note**, not a fault, because seating it is a convenience for a
human who merges, not a property of the tree.

### Why it matters beyond this file

A gate that fails on every clean tree teaches people to ignore gates — the same disease as the two-register
trap this PR cures. Two wards, one evening, both red for reasons that had nothing to do with the change being
judged: that is how a house stops believing its own red.
