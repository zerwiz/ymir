## A full sweep, and what it caught — all in my own doors

> *"fix all bug and test all files"*

Every gate and suite run; **three real failures**, and not one of them was in the product:

### 1. The inventory could NEVER be current

`bin/gates/inventory.sh` indexed `bin/` **including its own `README.md`**, and emitted that file's
**line count** in its row. Writing the index changed the number it had just written, so
`--check` failed the instant after a successful generate. A gate that can never pass is not a gate.
Its own size is now a dash — honest ("this is the index itself") and idempotent.

### 2. The ratchet fired on every NEW door

`usage-ratchet.sh` failed when the unused pile **grew** — and adding `usage-ratchet.sh` grew it
by one, because **a new door is uncalled until a skill names it.** That is Tuesday, not a
regression. The comparison is now *unused vs the growth of the shelf*: new doors are allowed;
**doors falling OUT of use still fail it**, which is the whole point. Proved both ways (a real
regression still fires; adding doors does not).

### 3. A test killed itself before its first assertion

`defaults-guard-seat-paths.test.sh` referenced `HOME_SEAT` **without ever setting it**, so under
`set -u` the suite died at line 48 — and a suite that dies early reports **green** in any wrapper
that only looks at the exit code of the wrapper. Ten checks now run.

### And one REAL gap, found by that test and left open on purpose

> `not ok - a guessed seat path in tools/ was NOT refused (rc=0)`

**`defaults-guard.sh` scans `bin/` and `.agents/` and does NOT scan `tools/`** — so a hardcoded
`$HOME/Documents/...` in a fleet MCP server (`tools/well-mcp`, `tools/snotra`, `tools/mcp-gateway`)
is **not refused today**. The fix is one line (add `tools/` to the ward's scan list), and it is
**not applied here** because a ward's scope change must be followed by the full sweep, and this
sweep is the end of the night. It is the first owed item, with the test that already proves the
expected behaviour.
