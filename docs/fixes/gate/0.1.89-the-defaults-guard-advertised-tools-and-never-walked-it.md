# 0.1.89 — the defaults-guard advertised `tools/` and never walked it

> The ward's own usage line said `default: bin/ .agents/ tools/ scripts/ src/`, while its
> unresolved-home walk visited **only `bin/` and `.agents/`**. A fleet MCP server could restate the
> operator's home path and the ward would never have seen it.

## A comment is not code

Widening the walk exposed **two more bugs, both mine, in opposite directions**.

The wider walk began reporting **nine** findings. Every one was `$YMIR_HOME` inside a `#`/`//`
comment or a Python docstring — the ward was grepping **prose as though it were an instruction**.
Comments and triple-quoted blocks are now stripped before the question is asked.

Two findings survived that, and both were worth keeping rather than allowlisting:

| line | what it was | now |
|---|---|---|
| `dispatch/registry.py` | `remedy="write $YMIR_HOME/config/agents.yaml …"` | *the operator's home* |
| `fleet/__main__.py` | `help="… (default $YMIR_HOME/hodd/data/fleet.json)"` | *under the operator's home* |

A user-facing message that reads like a shell fragment invites someone to paste
`$YMIR_HOME/...` into a file that cannot expand it. The house already had the right words; two
strings were speaking shell.

## A filter that drops what it cannot classify is worse than none

The **first** docstring stripper had no `else` branch for a line with two ordinary quotes, so it
silently ate every line shaped like `X="$SOMETHING"` — **hiding a real offender while appearing to
work**. It surfaced only because the fixture was tested in **both** directions:

```
a genuine offender (reads $YMIR_HOME in code)  → CAUGGED   ← the first version missed this
a docstring that only talks about the home      → clean
```

**A ward must be proved in both directions.** A test that only shows "nothing fires" passes just
as happily on a filter that fires at nothing.

## And the fixture was planting the wrong thing

`defaults-guard-seat-paths.test.sh` asserted *"a guessed seat path in tools/ is refused"* while
planting `$HOME_SEAT/mill/…` — a **variable**, which is a legitimate shape and which the ward
correctly declined to refuse. It now plants what its own comment always claimed: a path that
*decides* where the home is, `/home/someone/Documents/ymirhome/…`.

**The ward was right; the fixture was wrong.** That file's other failure (`HOME_SEAT` unbound under
`set -u`, which killed the suite at line 48) was written in the same sitting — so this suite had
never once reached its own assertions.
