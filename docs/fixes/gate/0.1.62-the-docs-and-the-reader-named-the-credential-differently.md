## gate · 0.1.62 · 2026-10-01 — the docs and the reader named the credential differently, so a user who followed the guide got nothing

### Why
The consent completed on 2026-10-01 and the grant is real — `MANAGANDR_OAUTH_REFRESH_TOKEN`
is in the operator's vault, encrypted, plaintext wiped. And then the first real read said:

```
"status":"unknown", "source":"none",
"reason":"no_oauth_client",
"missing":"MANAGANDR_CLIENT_ID,MANAGANDR_CLIENT_SECRET"
```

Because **the guide and the reader named the same two values differently**:

| | names the guide tells a user to write | names the reader read |
|---|---|---|
| client id | `GOOGLE_OAUTH_CLIENT_ID` | `MANAGANDR_CLIENT_ID`, `HEIMDALL_OAUTH_CLIENT_ID` |
| client secret | `GOOGLE_OAUTH_CLIENT_SECRET` | `MANAGANDR_CLIENT_SECRET`, `HEIMDALL_OAUTH_CLIENT_SECRET` |

So a user who followed the install guide **exactly** got `no_oauth_client` — the worst kind of
fault, because they did the right thing and the machine said no. This is the same lesson as the
workspace rename, learned twice in one day: **documentation and code must name a thing the same
way.** The reader's own header even advertised a fourth spelling (`MANAGANDR_CLIENT_ID/SECRET`)
while the shipped test suite passed, because no test ever set a client id at all.

### Fix
- The reader accepts **all three spellings** for both values, in a documented order, so every
  name in the house resolves to the same door:
  `MANAGANDR_CLIENT_*` → `GOOGLE_OAUTH_CLIENT_*` → `HEIMDALL_OAUTH_CLIENT_*`.
- **`bin/groa-update.sh` now reports the grant's state on every update**, in one line, in three
  words: granted / client present but not granted / not granted with the pointer to the steps.
  An update is when a user is most likely to meet a new capability, so the capability says
  whether it is live.

### Verified — the first real read
```
bin/calendar-ask.sh probe --json   → "status":"ok"  "source":"google"
GET :3889/api/calendar             → state ok · source google · 141 events in ±6 weeks
```
Real entries from the operator's own calendar (an AI-Adopters Club call, a Twitch slot, an
open house) — the reckoning is no longer synthetic, and the grid draws `state: "ok"` rather
than *"the reckoning is not granted"*.
