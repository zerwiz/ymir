## gate · 0.1.53 · 2026-09-29 — the push gate caught two scripts that guessed where the home lives

### Why
The release push was **refused twice** by `bin/guards.sh` before it ever left the seat,
and both refusals were correct. The four-shelves commit (`e350732`, the one the release
carries) added a home shelf to two scripts and wired it by literal path.

- **`bin/eindri-dispatch.sh` — "uses the home, never resolves it".** Its four-shelf
  skill walk read `$YMIR_HOME/.agents/skills/…` and, as a belt-and-braces fallback,
  restated one machine's layout: `[ -f "$HOME/Documents/ymirhome/.agents/skills/$s/SKILL.md" ]`.
  The guard's second class is exactly this: a file can be literal-free and still not know
  where anything is. It must **call** the resolver.
- **`bin/skill-find.sh:35` — "a home guessed".** `HOMESKILLS="$HOME/Documents/ymirhome/.agents/skills"`.
  The finder's whole purpose is to search four shelves on any computer; hardcoding one
  operator's home made the third shelf silently empty everywhere else.

### Fix
- Both scripts now source `bin/hoard-lib.sh` and call `ymir_home_root YMIR_HOME` — the one
  resolver (env → recorded → documented default). `eindri-dispatch.sh` exports the result;
  `skill-find.sh` derives `HOMESKILLS` from it and falls back to the repo root when no
  home is recorded, so a fresh clone still finds its shipped shelves.
- The redundant literal branch in `eindri-dispatch.sh` is **deleted**, not kept as a
  fallback: the resolved home already covers that shelf, and keeping it would restore the
  very guess the ward refuses.

### Verified
- `bin/defaults-guard.sh check` → `{"finding":"none"}` for both classes (was 1 default +
  1 unresolved).
- `bin/skill-find.sh --list` and `--where hnoss` behave; the home shelf is found through
  the resolver.
- `bin/eindri-dispatch.sh --help` unchanged; `bash -n` clean on both.
- `bin/guards.sh` passes; the branch pushed through the full gate (guards, branch-guard,
  fixes-guard: "3 notes, and the record speaks to the change").
