# 0.1.112 — the first system folder moved, and the index went blind until it was made recursive

## The move

`bin/{extension-api-check,workflow-check,usage-ratchet,home-index-check}.sh` → `bin/gates/checks/`.
**`no-delete-guard.sh` and `defaults-guard.sh` deliberately STAY loose**: the installed git hooks in
`.git/hooks/{pre-commit,pre-push}` reference `no-delete-guard` by path, so moving it breaks the hooks
until they are reinstalled. A structure is not worth breaking the gates that protect it.

## Two failures the move exposed — both real, both fixed

**1 · The register went blind.** 438 doors → **434**. `ls bin/*.sh` — in both the COUNT and the ROW
LOOP — stops at the first folder, so the moment `bin/gates/` existed, four doors silently vanished
from the register and `--check` still said **current**. Structure and index must move together:

```bash
find bin -name "*.sh" -not -path "*/.git/*" | LC_ALL=C sort
```

**2 · The moved doors could not find their own repo.** All four resolved `ROOT` by `dirname $0/..`,
which from `bin/gates/checks/` resolves to `bin/gates` — so `usage`, `workflows` and `ext-api`
went red immediately after the move. Fixed with the same marker-walk as 0.1.111: walk UP until
`.pi/` and `RULES/` both appear.

> **This is the cost of moving, stated honestly: a move is not a rename.** Every door that resolves
> its own location, and every enumerator that counts by glob, must be fixed in the SAME commit.

## Found while verifying, and NOT caused by the move

`ext-smoke` fails with `Cannot find module '/home/heimdall/ymir/.yggdrasil/pi-ext-la…'`. The
**first** entry in `.ymir-root` is the real repo, so my first guess — that a stale worktree is being
picked as the root — is **wrong**, and it is corrected here rather than left standing: the failure is
a module-resolution path, not a root-resolution one. With the module path supplied the same suite
reports **0 broken**.

**A correction in a note is the whole point of the append-only law**: the claim was made on a
plausible inference from one error line, and it was wrong.

## And the delete guard caught me

The failed move left a stray `bin/.agents/assets/agents/capabilities.md`, which an earlier
`git add -A` swept into a commit. `no-delete-guard.sh` refused its removal — **correctly** — because
Rule 11 says a file is MOVED, never deleted. It now lives in the vault's reference shelf with its
shape intact, and the reason is on the record.
