## gate · 1.0.1 · 2026-11-08 — a picture is not a transcript

### What

`private-guard` refused a legitimate whiteboard export:

```
whiteboard.png:7792: private hoard path
```

There is no private path in that image. The pattern `hodd/` was matched at byte 7792 of the PNG's **compressed** stream —
pixel data that happens to spell a path. The guard read a binary file as text and judged the accident.

**The fix:** a file that is binary media (`png · jpg · webp · gif · bmp · ico · tiff · heic · mp3 · wav · ogg · m4a · flac
· mp4 · mov · webm · mkv · zip · gz · tar · bz2 · xz · 7z · gguf · onnx · safetensors · bin · pt · pth`, plus anything
with a NUL byte in its first 8 KiB and no `.pdf` extension) skips the **text** scan, and says so on stderr:

```
binary media — the text scan is skipped; the operator's approval, bound to these exact bytes, is what judges it
```

The hash rule and the classified-document rule still run first, so a file whose digest is registered as protected is still
refused. What changes is only the byte-pattern scan, which was never meaningful on compressed data.

**Why not weaken it generally:** the text rules exist to catch what a model or a reader would *see*. On a PNG there is
nothing to see in the bytes — the content is judged where it always should be, by the operator's approval bound to the
exact bytes of what leaves (`snotra-approve.sh`). A picture is still refused if it is a registered protected document.

### Verified

- The same command that was refused now returns `private-guard clean` for the whiteboard's three files (the `.md`, the
  `.png`, the `.excalidraw`), and the note is printed to stderr for the PNG.
- A text file with a private path is still refused: `explained.md` was refused earlier today for carrying one, and the
  fix to *that* was to generalise the path, not to change the guard.
