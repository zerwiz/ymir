## Reporting it once is not proving it

> *"we have to prove and make sure all are used"*

**The proof of use is two measurable signals, and both can be false:**

```
· a test exercises the door      — named by anything under .agents/tests/
· a skill names it              — named by a SKILL.md or an asset under .agents/skills/
```

A door with **both** false is unused. That is the whole definition, and `capabilities.md` already
prints it per row — which is why the 61 were countable rather than a mood.

**So the proof had to become a gate.** `bin/usage-ratchet.sh` records the counts and **fails when
the unused pile GROWS**; the pile may only shrink, and shrinking it is an explicit act
(`--accept N`), never drift. Wired into `ci-verify`, so a door that quietly becomes unreferenced
cannot merge.

**Verified both ways** — not assumed:

```
first run              → "first baseline recorded: 61 unused — now it may only shrink"
baseline lowered by 5  → "the UNUSED pile GREW — 56 -> 61"  with the two honest answers named
real state             → "held or shrunk: 61 -> 61"
```

And two bugs of my own on the way, both found by running it: an apostrophe and then **backticks
inside the message** were being executed by the shell (`named: command not found`). A gate that
prints its own warnings by running them is a gate nobody trusts.

**What a ratchet does not do, and must not be asked to:** decide whether a capability is real. That
is the Allfather's judgement. The gate only enforces the direction — **unused may only grow by an
explicit, recorded act.**
