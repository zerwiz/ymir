## gate · unversioned · 2026-10-23 — main had two unresolved homes and a stale register, and every push inherited them

### Why

`guard.sh check` (the form `guards.sh` calls) refused two files on main:
`bin/mail/install.sh` printed `$YMIR_HOME/…` inside a sentence, and
`bin/time/snotra/snotra-approve.sh` tested `${YMIR_HOME:-}` with `-n` and never called
the resolver — a guarded test is not a resolution (Rule 07). Both made `defaults-guard`
FAIL, which makes the `ward` gate of `ci-verify` fail, which blocks every push from
any branch cut off main.

The capability register was stale for the same reason: five doors had landed
(`groa-agent.sh`, `seat.sh`, `learn-home.sh`, `mail-scan.sh`, `bin/mail/install.sh`)
without `.agents/assets/agents/capabilities.md` being re-rendered, so `capability`
listed 557 doors against a tree holding 575. `bin/README.md` was stale likewise after
the resolver line moved.

### The mends

| file | mend |
|---|---|
| `bin/mail/install.sh` | the sentence names the token's path in words ("inside the home"), never the variable |
| `bin/time/snotra/snotra-approve.sh` | resolves the home through `bin/vault/hoard-lib.sh` (`ymir_home_root`) before reading `$YMIR_HOME` |
| `.agents/assets/agents/capabilities.md` | regenerated by `bin/gates/capabilities.sh` — derived, never hand-edited |
| `bin/README.md` | regenerated by `bin/gates/inventory.sh` |
