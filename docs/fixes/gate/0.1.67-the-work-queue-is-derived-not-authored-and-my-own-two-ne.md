## What this note is really about

The Allfather, twice, and both times right:

> *"Why is the register a to-do list?"*
> *"We need a better to-do system, better tools for this."*

The to-do had been living in two wrong places — an in-session list that vanishes, and (twice, by
this same hand) inside a document that should not hold it. **A queue that is AUTHORED rots and
duplicates.** So `bin/gates/queue.sh` makes it a **view**: it reads `register.md` §1 and
`questions.md` — the only two places a row is ever added — and emits `plans/queue.md`. The check
mode is wired into `bin/gates/ci-verify.sh`, so a stale queue fails a gate exactly as a stale bin index
does.

```
$ bin/gates/queue.sh
wrote …/plans/queue.md
**Tally.** blocked=7 owed=7 open=32 done=2
$ bin/gates/queue.sh --check
queue --check: current (52 rows)
```

**And the second instruction — *"the scripts you are writing use other scripts that we have. as
tool calls"* — is the migration in plan 66 §6, and it is visible right here:** `ymir_find_home`
does not shell out to a new door, it *classifies*; `ymir_push` calls `git`; `ymir_free` calls
`bin/time/snotra/calendar-ask.sh`. The extension is the surface, the doors stay the logic.

## Two wards caught my own work, which is the point

1. `defaults-guard` refused `bin/gates/queue.sh` for writing a literal `$HOME/Documents/ymirhome` — the
   very rule it enforces. It now resolves through `ymir_home_root`, then `hodd.sh`, and **fails
   loudly rather than falling back to a guessed path**.
2. The `assets` ward refused the new extension until its **owning asset** was updated — Rule 06's
   governed-path law working on me. `assets/harness-integration/README.md` now records the tool →
   door map, and carries the known `dellingr` defect rather than hiding it.

A green tree here was not tidied; it was **earned twice from my own mistakes**.
