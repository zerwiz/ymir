## gate · 0.2.0 · 2026-11-03 — The capability register after the road

### Why
PR 487 added three bin doors and two tests and did not regenerate .agents/assets/agents/capabilities.md, so bin/gates/ci-verify.sh's capability gate failed on main and every open PR inherited the doubt. Regenerated.

### Files
- `.agents/assets/agents/capabilities.md`
### The fault

The constellation road (PR 487) added `bin/bridge/constellation.sh`, `bin/bridge/tests/test_constellation.sh`, and
`bin/gates/guards/constellation-grant-guard.sh`, and regenerated the **inventory** register (`bin/README.md`)
— which `guards.sh` checks. It did not regenerate the **capability** register
(`.agents/assets/agents/capabilities.md`), which a different gate checks
(`bin/gates/ci-verify.sh` → `bin/gates/capabilities.sh --check`), and which CI alone runs.

So the merge landed and the gate went red on `main`: `shell doors 664 → 668`, three missing rows, and the
`generated` date behind. Every open PR then carried a red check that was not theirs — which is precisely how a
collaborator's good work gets read as broken, and how a house learns to ignore a gate.

### What changed

`.agents/assets/agents/capabilities.md` regenerated (`bin/gates/capabilities.sh`). Nothing else.

### Why the pair was missed

Two derived registers are named almost the same way, generated by two doors, checked by two gates, and neither
door tells you the other exists. `bin/gates/inventory.sh` writes `bin/README.md`; `bin/gates/capabilities.sh`
writes `.agents/assets/agents/capabilities.md`. A change that adds a door must run **both**. That is the lesson
worth keeping: a generated file is only current if every generator that reads the tree has been run — and a
gate that only CI runs is invisible to the person pushing.
