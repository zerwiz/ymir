# 0.1.90 — three Actions workflows were invalid YAML; CI said only "workflow file issue"

> PR #270's checks read `gates=FAILURE` with no gate output. The run's own verdict:
> **"This run likely failed because of a workflow file issue."** The gates never ran — GitHub
> could not read the workflow that was supposed to run them, and one run sat red for a session
> before anyone looked at the *file*.

## Three files, two causes

| file | cause | fix |
|---|---|---|
| `eindri-monitor.yml` | unquoted scalar carrying a colon — `description: Check interval in minutes (default: 10)`; the colon ends the key | quoted |
| `eindri-merge.yml` | `--body "…` spanned lines whose continuation sat at **column 1**, ending the scalar so YAML read `- **Reviewed by:**` as a new block | continuation pulled inside the scalar |
| `daily-briefing.yml` | a heredoc body at **column 1** inside `run: \|` — the same break, in a heredoc | body indented to the block's own level |

**Column 1 is the tell.** In a YAML block scalar or a multi-line quoted scalar, content at column
zero silently ends the block, and the parser then tries to read the next line as YAML. Both broken
bodies are markdown that *looks* like it belongs at the left margin — because in the shell it does.

## And a stale path the rename had already left behind

`daily-briefing.yml` wrote the briefing to `svartalfaheim/zerwiz/**workspace**/memory/daily/` —
the path migration `0007` renamed to `projects/` three days ago. The workflow has been creating a
directory the house no longer reads, in a repo where `home-index-check` reports ten unindexed
shelves. Now `projects/`.

## The gate that should have caught it, before CI

`bin/workflow-check.sh` parses **every** `.github/workflows/*.yml` with PyYAML and prints the
offending **line and its content**. Wired into `ci-verify` as `workflows`. It degrades gracefully
when PyYAML is absent — the structural check still catches column-1 content inside a block scalar,
which is the bug that actually happened twice.

Proved in both directions:

```
all 8 workflows                        → "workflows","8","0"   rc=0
a planted broken workflow             → line 6: could not find expected ':'
                                         6| BAD: line at column one      rc=1
```

## Why this note exists at all

This is the *same lesson as 0.1.88*, one level up. There, a gate that could not **execute** sat
permanently red and read as "this environment is broken". Here, the workflow that could not
**parse** did the same. In both cases the fix is the same: **a thing that cannot start must say so
in its own words**, and something local must be able to tell "failed" from "never ran".
