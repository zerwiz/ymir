## gate · 0.1.56 · 2026-09-30 — asking a door what it does must never be the thing that raises it

### Why
I ran `scripts/start.sh --help` expecting usage, and **it raised the whole hall** — including a
full `npm install` — because `scripts/start.sh` had **no argument parsing at all**. The script's own
header documented `Usage: scripts/start.sh [--foreground]`, so the usage was *advertised* and
simply not implemented. `scripts/stop.sh` had the same shape: header promising `--force`, no
`case`, no `usage()`.

A door that fetches dependencies, raises processes, or kills them when asked *what it does* is a
trap: the question is the safest a human ever asks, and it must be free. The same rule the house
has written twice today — **cannot-run says so, never does something else**.

### Fix
- Both scripts answer `-h|--help` and `--version` **before any work**, in about 3 milliseconds,
  with a usage block naming what they raise (ports and env overrides) and where the logs are.
- `--help` cites only files that exist: the verify path is
  `.agents/skills/lifecycle/smoke_test.sh` (the NSR contract's own script), not a
  `scripts/smoke_test.sh` that was never there.
