## gate · 0.1.53 · 2026-09-29 — a third script guessed the home, and main itself could not push

### Why
This branch had to rebase: three PRs merged into `main` while the release was being
forged (#245 the gateway help slice, #246 the snotra call gate, #247 the seat/process/
helm). The rebase surfaced a fault that **`main` was already carrying**, and it is worth
recording as a class rather than a line, because the gate caught it only on the next push.

- `bin/snotra-iscall.sh:37` — `YMIR_HOME="${YMIR_HOME:-$HOME/Documents/ymirhome}"`.
  The call gate reached for the home by literal path. `defaults-guard` reads that as
  *"a home guessed"* and refuses the push.
- **The consequence is bigger than the line.** A ward that fails on the tree fails for
  *every* push, so after #246 merged no branch could be pushed from this seat at all —
  `main` included. The PR merged through the GitHub door, which runs no local pre-push
  hook, and the fault rode in unseen until the next rebase.

### Fix
`bin/snotra-iscall.sh` now sources `bin/vault/hoard-lib.sh` and calls `ymir_home_root
YMIR_HOME` — the one resolver (env → recorded → documented default) — exactly as
`eindri-dispatch.sh` and `skill-find.sh` now do. `${YMIR_HOME:-$HOME/Documents/ymirhome}`
is gone; it was a third spelling of a fact that has one home.
