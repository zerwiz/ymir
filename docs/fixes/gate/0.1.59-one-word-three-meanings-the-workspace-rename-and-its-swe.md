## gate · 0.1.59 · 2026-10-01 — one word, three meanings: the workspace rename and its sweeps

### Why
The Allfather: *"we have to many places called workspace in ymir home."* Measured, **six** places wore
one word for **three** unrelated meanings — and two of them were faults.

| # | Path | What it was | Now |
|---|---|---|---|
| 1 | `workspace/` | the repo's example registries | `registry/` |
| 2 | `hodd/workspaces/` | the operator's life's shelves | `hodd/life/` |
| 3 | `hodd/hodd/workspaces/marketing` | **a stray double-`hodd`**, nothing read it | removed |
| 4 | `svartalfaheim/<realm>/workspace/<project>/` | per-realm project shelves — **the canonical plan ledger's parent** | `…/projects/<project>/` |
| 5 | `svartalfaheim/wayof/` | **stale** (that realm was removed long ago) | renamed too; archiving is a separate, deliberate step |
| 6 | `workspace: work` | a **realm**, misnamed | `realm:` (a dispatched errand, with a deprecated alias) |

A rename that is only *believed* is not a rename: three readers still named the old path, the elder's
own law still named the old shelf, and nothing would have noticed until a seat failed at 3am.

### Fix
- **Migration `0007-one-word-three-meanings.sh`** — the template every seat's update runs. It moves
  by **`git mv`** inside the home (never copy-then-delete), removes the stray, and **verifies the
  append-only set by name** (runes, both secrets, the daily logs, every plan ledger) — and it
  **refuses to run at all** against a root that does not look like a Ymir home.
- **Every reader rewritten in the same change**: `bin/project-git.sh`, the gate API's registry path,
  `bin/syn-guard-pretool-check.sh`, `bin/snotra-capture.sh`, `bin/snotra-transcribe.sh`, the
  `nornir-jobs` and `snotra-meeting-ear` assets, `docs/workspaces.md`, `docs/Architecture.md`,
  `hodd/AGENTS.example.md`, AGENTS' outputs table, and `bin/eindri-dispatch.sh`'s plan reference.
- **The elder's law corrected by APPENDING**, not by editing: its old layout block stays as the
  record, and a dated correction below it names `projects/` as canonical. That is the law's own
  shape, and the smoke test *requires* the correction to be present.
- **The smoke test now proves the rename** (`rename-repo`, `rename-readers`, `rename-home`,
  `rename-stray`, `rename-ledger`, `rename-law`) **and sweeps for what a rename misses**: a
  `rename-sweep` grep for the old names across the runtime surfaces, and a `hardcoded-paths` grep for
  `/home/<user>/` and `/Users/<user>/` — the Allfather's own instruction, *"smoke testes must also
  find hardcoded filepaths"*.

### Two faults I introduced while mending it, and what caught them
1. **The migration resolved the wrong root.** `hoard_root` returns `$YMIR_HOME/hodd` — the *hoard*,
   not the *home* — so every path it looked for sat one level wrong: it **moved nothing, verified
   nothing, and still reported success.** It now asks `$YMIR_HOME` and then `hodd.sh path`, and
   **refuses** if the target does not look like a Ymir home. (The applied-marker had to be cleared
   by hand, because a migration that did nothing had recorded itself as done.)
2. **I guessed a home twice** — in the migration and in the smoke test — writing
   `$HOME/Documents/ymirhome` as a literal, one hour after writing the rule that forbids it.
   **`defaults-guard` caught both.** Both now resolve through the resolver or skip.
