## gate · 0.1.97 · 2026-10-03 — the register rendered differently under a different locale — LC_ALL is part of reproducibility

### Files
- `bin/capabilities.sh`

## The fourth reproducibility bug — and the odd one out

The first three were the corpus (nonexistent directories), the working tree (a `.pyc`), and
readdir order. This one is **collation**, and it had survived the sort fix:

```
locally  (UTF-8)   | a2abridge-ensure.sh | …      then  | a2a-mcp.sh |
CI      (C/POSIX) | a2a-mcp.sh         | …      then  | a2abridge-ensure.sh |
```

Because `sort` under a UTF-8 collation **ignores punctuation**, while `LC_ALL=C` compares bytes:
`-` (0x2D) sorts before `b` (0x62), so `a2a-mcp.sh` comes first in C and second in UTF-8. Same tree,
same content, two different registers.

**And the verdict moved too, not only the order** — which is the part that cost the time. A
capability name was matched as a **regex**, so `a2a-mcp.sh` also matched text where the dot was any
character at all. Two independent sources of machine-dependence in one generator.

## The fix, and the rule it states

```bash
export LC_ALL=C     # pins the collation of git, of sort, and of grep's character classes
grep -qF "$name"    # a capability name is a FIXED STRING — `.` must not match any character
```

**Reproducibility is not only about WHICH files you read; it is about how you order and how you
compare them.** Three bugs in a row were all of that same family, and the fourth one was hiding
*inside* the fix for the third.

Proved: rendered under the default locale and under `en_US.UTF-8` — byte-identical. A generated
file is now a function of the commit and nothing else.
