# 0.1.105 — my smoke test wrote 28 junk plans and 28 junk memories into the operator's vault

> The Allfather, listing files: `69-undefined.md` … `96-undefined.md`.
>
> **They were mine.** Every one of them. The Allfather's private plan ledger is the worst place a
> test can write, and my test wrote there — twice, in two different ways.

## What actually happened

`tools/extension-smoke.mjs` exists to prove the tools work after the Pi API repair. It called
**every** tool with `{}`, on the reasoning that an empty call is the mildest possible probe.

Two tools are not mild — they are **writers**:

| called with `{}` | what it did |
|---|---|
| `ymir_plan` | **created 28 plan files**, `NN-undefined.md`, each `# Plan NN — smoke` |
| `well_observe` (via `ymir-well`) | **appended 28 episodes** to `hodd/memory/well/episodes.jsonl`, each `"content": "undefined"` |

The plan files were untracked, so they were removed. The 28 episodes were an uncommitted
modification, so the committed well was restored. **Nothing was lost — because both were my own
garbage and neither had ever been part of the record.** Had they been committed, this would have
been 56 entries of history to explain forever.

## The three bugs underneath, in order

### 1. A writing tool did not refuse an empty call

```ts
required: ["slug", "title"],     // ← a HINT to a well-behaved model, not a guarantee
execute: async (_toolCallId, args) => { /* wrote a file */ }
```

`required` is documentation. It is enforced by nothing. The moment a *machine* calls the tool — a
test, a cron row, a script — there is no model to be well-behaved, and the file appears.

`ymir_plan` and `ymir_push` now **refuse what they cannot fill in**, and say why:

> `ymir_plan needs slug and title. This tool WRITES a file into the plan ledger, so it refuses to
> guess: an empty title once produced 28 files named NN-undefined.md in the operator's vault.`

### 2. `%%` escaped for `printf` but handed to `date`

```ts
printf '# Plan %s — %s\n\n**Opened %s.**\n' "$2" "$3" "$(date -u +%%Y-%m-%d)"
```

The `%%` was escaping the **printf** format — but that format belongs to **`date`**, which reads
`%%` as a literal `%`. Every plan created that night was stamped **`%Y-%m-%d`**, the format string,
not a date. It would have gone unnoticed for ever: the file looks plausible and the value is
obviously wrong only to someone who knows what a date looks like.

Verified: `**Opened 2026-10-03.**`

### 3. The test itself had a side effect on someone's records

The real defect. A test that can write to an operator's private vault is not a test; it is an
accident with a green tick — and **it reported success the whole time.**

Safe by default now:

- every tool is proved **callable** (`typeof execute === "function"`, and that it returns `content`)
- only an **explicit read-only allowlist** is actually **executed**
- `ymir-well` is out of the default set entirely, with the reason in the file

```
26 proved callable · 9 executed (read-only) · 0 broken · 0 writes
```

Adding a tool to the allowlist is now a decision somebody has to make deliberately. **Adding one to
the wrong list is no longer possible.**

## The rule, and it joins the family

> **A test must not be able to write to anything that matters. Verify the writer's refusal
> instead — that is the assertion worth having.**

This is the same shape as the week's other six, seen from the other end: every previous fault was a
check that measured a *proxy* instead of the thing. This one is a check that had **side effects** —
it measured nothing real and changed real state. The smoke test passed, twice, while corrupting the
Allfather's memory.
