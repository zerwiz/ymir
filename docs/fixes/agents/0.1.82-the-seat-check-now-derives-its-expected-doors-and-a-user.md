## And the door that "would not load" was my validator, not the door

`eindri.ts` failed every attempt at `node --experimental-strip-types --check`, at the same line no
matter what I changed. Bisected to the truth: **node's stripper rejects a `type X = …` alias**
("Unexpected identifier 'RunResult'"), while **pi's own loader handles them** — every existing
extension in this repo is full of TS types. So the file was never broken; **the check was**, and a
checker weaker than the real consumer proves nothing.

**Recorded so it is not repeated:** for TypeScript in this repo, `node --check` is not a validator.
The proofs that DO count are the ones the seats already use — deployed-and-loaded, brace/paren
balance, and a test that exercises the handler. `eindri` is deployed and counted (13/13); its
handlers run in the seat's own loader, and `ymir_errand` is the one surface still to be exercised
by a seated session.
