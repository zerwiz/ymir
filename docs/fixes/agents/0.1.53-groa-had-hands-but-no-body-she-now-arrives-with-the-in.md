# Gróa had hands but no body — she now arrives with the install and the update

**When:** 2026-10-23 · **Component:** agents · **Severity:** medium

## What was wrong

`bin/agents/groa-update.sh` is Gróa's **hands**: she fast-forwards, heals the home
forward and reports. But nothing woke her. A nightly updater had been written by
hand into one private home and seated on one machine — so a fresh install got a
caretaker with no one to keep it current, and an updated tree kept running the
older body that was copied weeks before.

## What changed

- **Her body is now in the tree:** `bin/agents/groa-agent/` — a brief
  (`README.md`), a five-step prompt with no writes and stop-on-error
  (`prompt.md`), the leash (`groa-agent.sh`: start · stop · status · tick ·
  check), and the seating script (`seat.sh`).
- **`bin/engine/ymir-install.sh`** gains `step_groa`, run after `step_autoboot`:
  it seats her on any host with systemd and skips honestly on a phone. `--check`
  reports whether her timer is already seated.
- **`bin/agents/groa-update.sh`** re-seats her after every update, so the features
  of the new tree are the features she runs. Never fatal: a failure to seat her
  never blocks an update.
- **`seat.sh --quiet`** exists for the update path, so re-seating does not run a
  full read-only check on every update.

## The naming

She is Gróa, the völva who renews — not "the update agent". The naming law applies
to a scheduled body as much as to a service: a job description is not a name.

## How it is proved

- `bash -n` on all three scripts.
- `seat.sh` on a real host installs OpenCode if absent, writes the runner to
  `~/.local/bin/`, installs `groa-agent.timer` with a per-host stagger, and proves
  the leash with one `check`.
- Her first check on `zerwizserver` reported a **diverged** tree (1021 local /
  1640 remote commits, dirty) and npm 0.1.52 vs 0.1.53 — and changed nothing.
  Skipping a tree she cannot fast-forward is the correct act, and now it is
  recorded by her own body rather than by an operator noticing.

## Note for the reviewer

`seat.sh` may run `sudo npm i -g opencode-ai` when OpenCode is absent. That is the
only privileged action, it is a package install, and it is skipped when OpenCode
already answers.
