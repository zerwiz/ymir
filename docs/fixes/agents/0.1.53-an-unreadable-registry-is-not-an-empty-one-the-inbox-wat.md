# An unreadable registry is not an empty one — the inbox watcher watched nobody, silently

**When:** 2026-10-23 · **Component:** agents · **Severity:** high

## What was wrong

`bin/people/inbox-watch.sh` runs three times a day (`@dev 08:20 · 14:20 · 19:20`)
to announce mail from the people we work with. A YAML fault in
`$YMIR_HOME/hodd/identity/collaborators.yaml` — one unquoted `2026-10-23:` inside a
folded `notes:` block — made `collaborators.sh list` crash.

The watcher piped that error into `2>/dev/null` and treated the empty result as
**"no people in the registry"**, exiting **0**. So for part of a day it reported
success three times while watching nobody, and no reply from any collaborator
could have been announced.

## What changed

The watcher now separates the two states:

- **registry unreadable** → prints *"the people registry could not be read — NOT an
  empty registry"*, shows the last lines of the error, names the remedy
  (`bin/people/collaborators.sh check`) and exits **1**;
- **registry readable but empty** → the old, honest message, exit 0.

## Why this matters more than the YAML

The YAML is fixed. The fault that matters is the shape: **any watcher that
conflates "I could not read" with "there is nothing" is a watcher that can be dead
for days and report health.** The same shape appeared twice today — Plane's
password file disagreeing with its container, and a mailbox absent from the gate's
user records. Absence is a fact only when the read succeeded.

## Proof

- `bin/people/collaborators.sh check` → `5 people, valid`
- `bin/people/inbox-watch.sh --dry-run` → reads all four addresses, reports the
  one new message from Reygan instead of "no people".
