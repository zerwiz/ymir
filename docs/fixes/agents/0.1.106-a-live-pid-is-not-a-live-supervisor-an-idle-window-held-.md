# 0.1.106 — a live pid is not a live supervisor: an idle window held the helm for two days

> The Allfather: *"why dont the gna arm keep ing you alive?"* — then: *"that session are not on..
> so you need to take the arm"*, and: *"i have no pi window that gets kept alive and gets the
> brokk message in to it"*.

## What the measurement showed

```
watcher     pid 1206     2d09h alive   heartbeat 3-5s old   ← healthy the whole time
helm lock   pid 1408704  2d01h alive   CPU time 21 minutes  ← an idle pi window
this session            pid 69808     a different window entirely
```

The watch was never down. **The supervision had a nominal owner and no actual one**: an idle `pi`
process had held the helm for two days, and `gna_watch_arm` answered `read-only` to the one session
that could actually supervise.

## The bug, exactly

```ts
if (ownership === "other")   return { ok: false, message: "read-only — lock held by another session" };
if (ownership === "missing") { reclaimStaleLock(...); return startArm(...); }

return pidAlive(lockPid, recordedStarttime) ? "other" : "missing";
```

`pidAlive` is a **proxy** for *"this session is supervising."* The thing itself is the supervisor.
Measured on 2026-10-03: the idle window's arm child was long dead, so nothing could ever reclaim the
helm — and the reclaim path was written for *"dead, zombie, or recycled pid"*, which this was not.

> A pid is a proxy for "this session is supervising." The thing itself is the supervisor process.
> **Ask about the thing.**

## The fix

Ownership now requires a **live supervisor**, recorded when an arm child starts and cleared when it
exits:

```ts
if (!/^[0-9]+$/.test(childPid)) return "missing";   // no verifiable supervisor
if (!pidAlive(childPid, ""))    return "missing";   // supervisor gone — reclaim it
return "other";
```

with `<lock>.child` written beside the lock on arm, removed on release, and removed by
`reclaimStaleLock` when it takes the helm. **No sidecar means `missing`**, so a holder that never
recorded a supervisor can never block a session again — which is precisely the pre-fix world.

## Proved in all three states, and the proof itself had to be fixed first

```
1. holder alive, supervisor ALIVE   -> other     do not steal a working session
2. holder alive, supervisor DEAD    -> missing   reclaim  ← the fix, and the real failure
3. no sidecar at all                 -> missing   reclaim  an unrecorded holder cannot block again
```

**The first version of that proof checked only the child's pid *format* and reported `other` for a
dead supervisor** — the exact failure it was written to disprove. It was caught because the output
contradicted the expectation, not because anything failed. The correction is the point worth keeping:
a test that *cannot disagree* with the code tests nothing, so the proof mirrors the real rule
(format **and** liveness) rather than a simplified one.

## What I did NOT do

I did not kill the idle window. I cleared the helm lock (backed up first) so the reclaim path could
fire, so nothing of his was destroyed to fix my measurement — and I checked my own ancestry first,
because if that pid had been *this* session, clearing the lock would have been the wrong move in a
different and much more expensive way.
