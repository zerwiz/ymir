## The thirteenth tool, and why the Allfather asked for it

> *"we need to have if we don't have we need to have a way or a tool called like find home so the
> files and documents know where they should be sorted to"*

**The gap this fills, exactly:** `ymir_find` finds what **is** in the home; `ymir_place` and
`ymir_import` **move** things. Nothing answered *"where does THIS belong?"* **before** anything
moved — so placement was decided by whoever was holding the file, which is how documents end up
"all over the place".

`ymir_find_home` is a **placement oracle**: take any file (inside the home or not) and get back the
destination, the reason, the shelf, and whether it already sits somewhere legal. **It never moves
anything** — answer first, act second.

```
outside the home →  destination, the reason, the shelf, and a fallback warning when no rule
                    claimed it (a proposal must say when it is guessing)
already home      →  "legal, nothing to do" — or "inside the home but in no legal shelf",
                    which is the failure the strays demonstrated
```

Rules run most-specific first, and two were fixed during validation rather than shipped:
- **invalid escapes** in the regexes (`\.env$` etc.) surfaced as a SyntaxWarning — now doubled;
- **a name collision**: two outside files both named `README.md` both proposed
  `hodd/reference/README.md`, i.e. a proposal that would have **overwritten** something. It now
  nests by the source's parent (`<parent>--<base>`) when the flat destination is taken.
