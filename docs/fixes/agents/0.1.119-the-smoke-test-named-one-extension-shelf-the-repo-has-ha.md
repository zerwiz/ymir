# 0.1.119 — the smoke test named ONE extension shelf; this repo has had two

After the bin restructure merged, `ext-smoke` went red with:

```
NO ROOT — set YMIR_ROOT or run bin/seat/valknut-load.sh --all --global
extension_smoke[4]{called,verified_not_executed,broken,skipped}:
  "0","0","11","0"
```

**The root WAS resolvable** — the third door walks up from `import.meta.url` to the checkout.
The bug was one level down: it accepted the checkout only if `.pi/shared/extensions` existed, and
this repo has carried **two** homes for the extension shelf.

> **A test that hard-codes ONE path for a thing that has had two paths is a test that fails
> whenever the second path wins.** The loader resolved the ROOT fine and then failed to find a
> single extension in it.

Both doors now accept either home, and the suite reports **9 called · 17 verified · 0 broken · 2
skipped**. Nothing under `.pi/` was touched — the fix is in the test, which is where the wrong
assumption lived.
