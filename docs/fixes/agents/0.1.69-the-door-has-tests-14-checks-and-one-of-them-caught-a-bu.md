## Fourteen checks, against a real home — and one caught a bug in its own tool

> *"tests — all my missing are getting it in the right way so we know if the system works."*

The suite builds a **real** temporary home in a **real** git repo — no mocks, because the
doors under test are `git`, `find` and the resolver, and a mock would prove nothing about them.

Covered: the door registers its tool set · `header --check` finds documents with no header ·
`--apply` writes the **full** field set · `kind` is derived from the path · `grade` is left
`unmeasured` for the grader · **`verified` is left EMPTY** because nobody proved it · `--apply` is
**idempotent** (a second run changed nothing — a header written twice is a rewrite, which is the
fault this whole plan is against) · the fill rate is reported · a field nobody has earned reads
**0%** · `find_home` recognises a legal in-home path and **refuses** a credential-shaped one ·
`dellingr` grades and prints its formula · `push` refuses a credential path.

**The test earned its keep on first run.** The fill-rate counter was counting the **trailing
space** after `verified: ` as a value, so a document that declared nothing scored **100%** on ten
of thirteen fields — the exact failure the tool exists to prevent, inside the tool. The counting
is now obviously correct: split on the first colon, trim, and treat empty / `unmeasured` /
`canonical: false` as **no declaration**.

**A measure that cannot measure is worse than no measure** — the same law as `dellingr`
refusing an age it cannot read, now applied to the checker itself.
