## agents · 1.0.1 · 2026-11-06 — The sweep stops burying live work

### Why
An errand was judged dead 3m59s after launch because herdr said 'done', which means idle, not finished — and the once-only delivery mark then froze the wrong verdict.

### Files
- `bin/agents/eindri-liveness.sh`
- `bin/agents/eindri-acclaim.sh`
- `tests/test_eindri_liveness_grace.sh`
- `bin/gates/ci-verify.sh`
- `docs/features/eindri-isolated-workers.md`
### What was wrong — a quiet pane was read as a dead one

`state/jev-preset-bench.meta` says it plainly:

```
launch_iso=2026-11-05T23:10:11Z
liveness=dead corrected=2026-11-05T23:14:10Z evidence=the agent in w3F:p1 is done and left no terminal line
```

**Three minutes fifty-nine seconds.** The pane was working, mid-errand, running tool calls. But herdr reports an
agent as `done` whenever it is *idle between turns*, and `judge()` treated `done` as a death certificate.

The verdict alone would be survivable — a wrong line, written late. What made it costly is what happened next:

1. `correct()` appended `failed:` to the status, so every later `judge()` saw a **terminal** claim and returned
   `SKIP`. The record was closed against its own correction.
2. It then spent the once-only `dead` mark. When the worker finished hours later and ran `eindri-acclaim.sh`,
   the sweep had already filed `state/eindri-reports/<id>.md` from its guess *and* spent the `report` mark, so
   acclaim answered — correctly, by its own law — **"already delivered — no duplicate wake"**. The true terminal
   word went into `.status` and nowhere else; the durable report kept *"the worker never ran eindri-acclaim.sh"*.

**A claim that can only be corrected by the mechanism that produced it is not a record.**

### The fix — three narrow changes, no new machinery

**1 · The settling grace (`verdict_dead`).** A quiet pane is evidence of quiet; only distance from the launch makes
it evidence of death. Below `YMIR_LIVENESS_GRACE_MIN` (default 10) the verdict is **SETTLING** — a token that is not
`DEAD`, so `judge_rows` takes no action on it. Past the window the old verdict returns. Measured against the case
that produced it: the same seat at 3m59s is now `SETTLING`; at two hours it is still `DEAD`.

**2 · The inferred failure names itself.** The sweep now writes `failed: [liveness] …`, keeping the `failed:` prefix
every consumer matches (`eindri-acclaim.sh:101`, `eindri-heartbeat.sh:76`, `eindri-liveness.sh:106`) while marking the
word as **inferred**, not the worker's own declaration.

**3 · A worker's word outranks an inference.** `correct()` returns untouched if the newest line is already a worker
terminal (`done:`/`needs-decision:`/`paused:`), so a finish that lands between the verdict and the write is never
overwritten. And `eindri-acclaim.sh` now heals a report shelf that carries the sweep's header — *"finished without a
terminal word"* — replacing the guess with the terminal line and delivering the correction under **its own kind**
(`corrected`), so a spent `report` mark cannot mute it.

### Proof

`tests/test_eindri_liveness_grace.sh`, wired into `bin/gates/ci-verify.sh` as the `liveness-grace` gate:

```
pass: a 60s-old quiet seat reads SETTLING
pass: a two-hour-old quiet seat still reads DEAD
pass: YMIR_LIVENESS_GRACE_MIN=0 makes the young seat DEAD
pass: check corrected nothing
```

And the heal, proved by hand against a scratch state: a shelf reading `# demo — finished without a terminal word`,
with the `report` mark already spent, after `eindri-acclaim.sh demo`:

```
shelf  → "done: the real work landed at sha abc123"
ledger → demo.corrected (beside the spent demo.report)
wake   → "eindri demo CORRECTED: the sweep's snapshot was a guess — …"
```

### What this does not fix

- **The mark is still spent on one guess.** The grace makes the guess rarer, not impossible; a genuinely dead seat
  inside its first ten minutes is now caught at the next sweep instead of this one. That is the right trade for a
  worker that runs for hours, and it is a deliberate one.
- **`failed:` written by an older sweep stays terminal.** A home carrying pre-fix false verdicts keeps them; this
  repairs the mechanism, never the history (Rule 06).
- **The root restart for `/v1/systemone`** is untouched and unrelated — still the Allfather's one command.
