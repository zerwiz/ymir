# Gróa gets a body — the updater now ships with install and update

**When:** 2026-10-23 · **Component:** agents · **Severity:** medium

## What was wrong

`bin/agents/groa-update.sh` is Gróa's **hands**: she fast-forwards, heals the
home forward, and reports. But nothing woke her. A nightly updater had been
written by hand into one private home and seated on one machine — so a fresh
install got a caretaker with no one to keep it current, and an updated tree kept
running the body copied weeks earlier.

The same drift hid three scripts the private schedule already called but which
had never been committed (`bin/assistant/smoke.sh`,
`bin/time/snotra/audio-retention.sh`,
`bin/time/snotra/meeting-record-guard.sh`), so those jobs resolved on one machine
and failed everywhere else.

## What changed

- **Her body is in the tree:** `bin/agents/groa-agent/` — a brief (`README.md`), a
  five-step prompt with no writes and stop-on-error (`prompt.md`), the leash
  (`groa-agent.sh`: start · stop · status · tick · check), and the seating script
  (`seat.sh`).
- **`bin/engine/ymir-install.sh`** gains `step_groa` (after `step_autoboot`): seats
  her where systemd exists, skips honestly on a phone, and `--check` reports
  whether her timer is seated.
- **`bin/agents/groa-update.sh`** re-seats her after every update, so the features
  of the new tree are the features she runs. Never fatal.
- **`seat.sh --quiet`** for the update path, so re-seating does not run a full
  read-only check each time.
- **Her home is resolved** through `bin/vault/hoard-lib.sh` (`ymir_home_root`),
  never restated — `defaults-guard` refuses the alternative.
- **The three missing scripts are committed**, unchanged.

## The naming

She is Gróa, the völva who renews — not "the update agent". A scheduled body is a
subsystem and is named like one.

## How it is proved

- `bash -n` on her scripts, `seat.sh`, `groa-update.sh`, `ymir-install.sh`.
- `defaults-guard` → every path resolves through the one resolver.
- `cron-guard` → every referenced script ships in the repo.
- Seated on `zerwizserver`; her first read-only check reported a **diverged** tree
  (1021 local / 1640 remote commits, dirty) and npm 0.1.52 vs 0.1.53 — and changed
  nothing. Skipping what she cannot fast-forward is the correct act.
