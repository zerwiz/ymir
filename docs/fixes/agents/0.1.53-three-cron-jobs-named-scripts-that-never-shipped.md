# Three cron jobs named scripts that never shipped — the schedules were dead on every other seat

**When:** 2026-10-23 · **Component:** agents · **Severity:** medium

## What was wrong

The private schedule (`$YMIR_HOME/config/cron.yaml`) ran three commands whose
scripts existed only in one working tree, never committed:

```
bin/assistant/smoke.sh
bin/time/snotra/audio-retention.sh
bin/time/snotra/meeting-record-guard.sh
```

Nornir runs every job from the repository root, so on any fresh install — and on
every other seat — those three lines resolved to nothing and failed silently.

**How it was found:** the cron ward refused a push. The push was mine (Gróa's
body); the fault was not.

## What changed

- The three scripts are now **tracked** in the repository, unchanged, so the
  schedules resolve everywhere.
- `cron-guard.sh check` answers `every referenced script ships in the repo`.

## Why it was hidden

They were written on one machine, used there, and never committed — the same shape
as any drift that only bites another seat. The ward is what caught it, which is the
ward doing its work.

## Not changed

No schedule was altered and no job was removed; only the missing scripts were
added. Their behaviour is exactly as it was on the machine that had them.
