## agents · 0.1.60 · 2026-10-01 — the recovery playbook named a door that does not exist

### Why
Recovering the two errands on 2026-09-30 cost real time because `.agents/skills/syn-recovery/SKILL.md`
sent me to doors that are not there:

- it named **`bin/brokk-control.sh <id> interrupt|exit|relaunch`** — **that script does not exist**
  on this house;
- the door that *does* exist, `bin/agents/eindri-control.sh`, offers only `interrupt | exit | read` —
  **there is no `relaunch` verb**;
- and the escalation steps named `--note '<progress so far>'`, which the real relaunch road does
  not take.

So the playbook's own recovery path could not be walked. A recovery playbook whose commands do not
exist **costs a recovery** — it is worse than no playbook, because it is trusted and it is wrong.

### Fix
The playbook now states the real road, and states the absence plainly rather than implying it:

```sh
bash bin/agents/eindri-control.sh <id> interrupt              # stop it
bash bin/agents/erindi-brief.sh <id> --relaunch               # scaffold the brief
# …fill the brief's {TASK} with what it did and what is left…
bash bin/agents/einherjar-spawn.sh <id> --relaunch --harness <h> --model <m>
```

It also records the two refusals that road gives for correct reasons (a `{TASK}` still in the
brief; a seat record that already stands), and notes that `brokk-send` resolves a *registered*
`eindri-homes.md` home — a local worktree errand has none, so its steer goes through its own wake
queue.

### And the measurement lesson, written where it will be read again

The same recovery produced a false verdict: a worktree read as `0` commits against
`origin/main..HEAD`, and I filed two **delivered** errands as failed (#264 and #262 both merged) —
because the commits were on the **remote** branches. The playbook now says, before filing a
failure: *check `git log --oneline origin/<branch>` and `gh pr list`.* A worker at its context
ceiling is not evidence of failure; only its branch is.
