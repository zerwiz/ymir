## agents · 0.1.98 · 2026-10-03 — a tool that registers is not a tool that runs — calling the handlers found four bugs

### Files
- `.pi/shared/extensions/elder.ts`

## The split produced a door that registered beautifully and did nothing

`elder.ts` was cut out of `ymirhome.ts` by extracting five `registerTool` blocks. Every block parsed,
every file loaded, and a smoke test that registered each extension reported

```
elder: 5 tools — ymir_note ymir_plan ymir_push ymir_daily ymir_dellingr
```

**Then the first real call threw `run is not defined`.** The blocks referenced two things that lived
*outside* them in the original file and did not travel:

| missing | what it was | consequence on first call |
|---|---|---|
| `run()` | the shared door-runner | every handler threw |
| `GRADES` | a local `const` inside `ymirhome`'s function | `ymir_dellingr` threw |
| `ROOT_BIN` | the resolved repo root | any handler that named a door |

Three more bugs surfaced only because the test kept **calling** handlers:

- **`ymir_daily` created a directory and then `cat`ted a file inside it that had never existed** —
  asking for a day with no entries failed with `cat: … No such file or directory` instead of saying
  *"no entry yet for that day"*.
- **`ymir_push` threw** `Cannot read properties of undefined (reading 'map')` on a missing argument.
  `required` is a hint to a well-behaved model, **not a guarantee**; a tool must *say what it needs*.

## The rule this earns

> **A tool that registers is not a tool that runs.**

0.1.95 said *deployed is not loadable*. This is the same failure one level up, and the fix is the
same in kind: **prove the thing by making the check call it.** The smoke test that moved these five
tools only *registered* them and passed. The version that *invoked* each handler with empty
arguments found four bugs in the first minute — one of them (`run is not defined`) meaning the whole
door had never worked since it was created an hour earlier.

**What a registration-only smoke test cannot see:** a missing helper, a captured local, a path that
does not exist, an argument contract nobody honoured. All four live in the handler.

## Also fixed here: collation (0.1.97's sibling)

CI called the register stale while a clean checkout rendered it identically, again. This time the
cause was **collation, not order**: `sort` under a UTF-8 locale ignores punctuation, while
`LC_ALL=C` compares bytes — so `a2a-mcp.sh` and `a2abridge-ensure.sh` swap places between this seat
and a runner. And the *verdict* moved as well, because a capability name was matched as a **regex**:
`a2a-mcp.sh` also matched any text where the dot was some other character.

```bash
export LC_ALL=C      # pins the collation of git, of sort, and of grep
grep -qF "$name"     # a capability name is a FIXED STRING
```

**That is the fourth reproducibility bug in a row, and the third hid inside the fix for the
second.** Reproducibility is not only *which files you read* — it is *how you order them and how you
compare them*. Verified: rendered under the default locale and under `en_US.UTF-8`, byte-identical.
