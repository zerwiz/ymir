## The survey first — so this door duplicates nothing

The Allfather: *"for herdr find all were using for that now"*. Measured before writing a line:

```
bin/herdr-agents.py                 the seat/agent inventory
bin/herdr-ensure.sh                 Þjazi: guarantee the terminal backend Ymir needs
bin/herdr-run.sh                    raise an Eindri, by the grain the errand fits

.pi/shared/extensions/herdr-agent-state.ts   reports agent state into the pane
consumers: a2a-serve.{py,sh} · eindri-* · omarchy-install.sh
```

So the door registers **only** what is distinctLY its own: `ymir_seats` (where the work is) and
`ymir_close_dead` (close a shell whose owner is gone, refuse a live one). Three dead shells from the
failed launches outlived their errands — a shell whose owning process is gone cannot answer, and
until tonight nothing named them.

## tmux is not a nicety — it is the fallback

*"could we also support tmux maybe in this extension"* — and he is right to ask, because the house
law is **herdr-first with tmux as the fallback** (`einherjar-spawn.sh`). A seats door that only
spoke herdr would be **blind exactly when herdr is down**, which is the moment you most need to see
what is stranded. So tmux is read **natively** (`list-panes -a` with pid), not shimmed through
herdr, and liveness is `kill -0` on the pane's pid.

## OpenRig — read, and deliberately NOT copied

He named it twice as *"the reference for what it made good into herdr"*. I had filed it that way
too. **It is not a donor — it is a rival rig**: `@openrig/cli`, its own kernel, TUI, queue and
seats, on **cmux**, writing a `~/.tmux.conf` block and able to enable cmux's automation socket.
Vendoring its shape would put a second rig, a second queue and a second TUI beside ours — the very
"the same thing over and over" he stopped me from building with the extensions.

**The one lesson worth taking** is its death-check: *a seat whose owning process is gone is a fact,
not a pane.* That is `ymir_close_dead`, and it is the whole borrow.
