# Two files guessed the home — the ward refused the push until both resolved it

**When:** 2026-10-23 · **Component:** agents · **Severity:** low

## What was wrong

`defaults-guard` found two places that restated where the home lives instead of
asking the one resolver:

- `bin/agents/groa-agent/groa-agent.sh` (new, mine) — fell back to
  `$HOME/Documents/ymirhome`.
- `.agents/harness/opencode/plugins/ymir-tools.ts` (pre-existing) — same fallback
  after the resolver failed.

A guessed home is how one seat's work lands in another seat's vault, and it is
exactly what Rule 07 forbids.

## What changed

- **Gróa** now sources `bin/vault/hoard-lib.sh` and calls `ymir_home_root`, with a
  state-dir fallback only when no home resolves at all.
- **The plugin** no longer invents a path: if the resolver yields nothing it throws
  `YMIR_HOME not resolved — ask bin/vault/hoard-lib.sh, never assume it`.

## Proof

`bin/gates/guards/defaults-guard.sh check` → `every path resolves through the one resolver`.

## Note

The second fault was already on `main`; it blocked any push, not only this branch.
Both are fixed here because a guard that always fails is a guard everyone learns to
ignore.
