## runtime · 0.2.1 · 2026-11-03 — Who is in a Telegram chat — and what the Bot API will not say

### Why
The bridge exposes no member list, so an agent cannot see who else is in the room. A door now asks Telegram for the chat, the count and the administrators, and states the limit: a bot cannot enumerate ordinary members.

### Files
- `bin/notify/telegram-members.sh`
- `docs/features/telegram-members.md`
### The fault, and the honest half of it

The Allfather asked, in a chat where a partner was present: *"can you see his participant?"* The answer was no —
and the reason is two faults stacked:

1. **The bridge gives the agent no member surface at all.** `@llblab/pi-telegram` never calls
   `getChatMember`, `getChatAdministrators` or `getChatMemberCount`; it hands the turn's text and nothing about
   who else is in the room.
2. **Telegram itself will not enumerate ordinary members.** The Bot API gives a bot the chat, the count, the
   administrators, and one member at a time *if you already know their id*. There is no "list everyone" call, for
   any bot, ever.

So a door that claimed to show "all participants" would be lying, and a fix that patched the bridge to try would
fail at the API. This change does the part that can be done honestly, and names the part that cannot.

### What changed

- **`bin/notify/telegram-members.sh`** — `me` · `chat` · `count` · `admins` · `who`, reading the bot token from
  the harness profile (`PI_TELEGRAM_CONFIG`, default `~/.pi/agent/telegram.json`) or `TELEGRAM_BOT_TOKEN`, and
  requiring `--chat` because guessing the room is the one thing it must not do.
- **`docs/features/telegram-members.md`** and a catalogue fragment.
- Measured live: `me` → the bot; `count --chat <the operator's chat>` → 2; `admins` on a private chat →
  Telegram refuses with *"there are no administrators in the private chat"*, which the door reports rather than
  turning into an empty list.

### What is still needed for "see everyone"

A **roster built from who speaks**: every arriving message carries its sender and its chat id, and recording
those gives the members Telegram will not list. That needs the bridge to hand the sender and the chat id to the
agent — an upstream change in the harness package, not something this tree can fake. Until then the honest
answer to "who is in this group?" is: the count, the administrators, and everyone we have heard from.
