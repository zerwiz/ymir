## runtime · 1.4.1 · 2026-10-26 — the well has a policy: gate, types, provenance, corrections, and a continuous forgetting pass

### Why

Plan 136 — *the best memory an AI best friend can have*. The well had a store, a
bridge and a log, and **no practice**: every write was accepted (a shelf, not a
mind), an episode could be corrected only by writing a contradicting one beside it,
recall searched the whole house before it wondered whose memory it was, and the
grading system (nýr · eldri · forn · safn) was a quarterly intention. Measured
2026-10-26 on the house well: **122 episodes, 20 already void-tagged by hand, 0 graded
runs ever, last recall 29 days old, every episode typed `episodic` by default.**

### Fix

- **`bin/records/mimir-policy.py` (new, stdlib only)** — one policy with five
  faces. The **gate** asks three questions (behaviour · commitment · decision) and
  drops a write that answers none; it refuses secrets and the vault outright. It
  canonicalizes dates/clocks/names, deduplicates (hash, then Jaccard ≥ 0.85), scores
  by novelty × relevance, and routes each write to **episodic · semantic · procedural**.
  Provenance (`src:`, `scope:`, `conf:`, `privacy:`, `retain:`, `task:`) is stamped as
  tags because the engine refuses any provenance but `user|tool|external`.
  **Corrections** chain by id (`corrects:`/`retracts:`/`consolidates:` + `void:` on the
  original) and never erase. **Grading** is a pass: unscoped decay, exact-duplicate
  consolidation, retention archiving, and a document moved to `hodd/reference/` only
  when it declares `superseded_by:`. The count is checked before and after — a run
  that lowers it is a failure, not a tidy-up (Rule 20).
- **`bin/bridge/mimir-bridge.py`** — `/observe` and `/remember` gate and answer with
  the decision; `/recall` builds the **slice** (store · tag · since · until · agent)
  before similarity, excludes voided/archived, and fills from the slice when the index
  lags; `/correct`, `/retract`, `/grade` added; `/episode` returns the correction chain;
  `/health` carries last observe/recall/daily/prune and the shelf split; `ensure_schema`
  adds the engine's provenance columns if an old store lacks them and an index on
  `episodes(timestamp)`; every recall flushes the access log (the engine buffers it, so
  four recalls left `last_recall` reading "never").
- **`bin/records/mimir.sh`** — `memory` (the health row), scoped recall (`--store` · `--tag` ·
  `--task` · `--since` · `--until`), `correct`, `retract`, `why`,
  `grade`, `policy`, `start|stop|status` (Eir's mend called `mimir.sh start`, a verb that
  did not exist); scoped `recall`; gated `observe` that works offline (the gate is
  stdlib, so an outage costs indexing time, never a lesson); one log resolution shared
  with the bridge and the policy.
- **`bin/records/mimir-recall-today.sh` (new)** — the session's opening recall, keyed to
  the day's stated topic (`state/.session-topic`, else today's daily-log bullet, else the
  newest forge order), scoped to 14 days. Sága's new `RECALL` section calls it.
- **`bin/agents/eir-doctor.sh`** — a **`memory`** surface (well size, last observe, last
  recall, last daily entry, last grading run) beside the existing `well` port check.
- **`bin/time/nornir-job-memory-housekeeping.sh`** — the grading pass runs nightly
  (`--apply` only after the backup succeeds), so forgetting is continuous, not quarterly.
- **`bin/records/mimir-log.py`** — `export`/`reseed` carry `provenance` and `quarantined`,
  so a re-seed restores the words **and** the trust.
- **`.pi/extensions/ymir-well.ts` · `.pi/extensions/ymirhome.ts` · `tools/well-mcp/server.ts`**
  — the tools pass the new fields and **report a drop as a drop**: a gate that answers
  `stored: false` must not read as success.
- **`bin/records/well-selftest.sh`** — extended with the gate's own checks (drop · keep ·
  duplicate · the policy self-test). New `.agents/tests/well-policy.test.sh` proves the
  whole chain on a **throwaway** well: 23 checks, including scoping by task.

### Verified

- `python3 bin/records/mimir-policy.py --self-test` → `0,"PASS"` (25 checks, temp store).
- `.agents/tests/well-policy.test.sh` → `well-policy[1]{pass,fail,skip}: 23,0,0` — gate
  drops/keeps, types, dedupe, secret refusal, shelf isolation, task scoping, correction
  chain, retraction append, grading apply, health row.
- `bin/records/well-selftest.sh` → `0,"PASS"` (offline: scoped recall, refused flag, gate).
- On the house well, read-only: `mimir.sh memory` → `122 eps · 20 void · observe today ·
  recall 29d · daily 1d · prune never — grading has never run`; `grade` reports
  `nýr 4 · eldri 118`, two exact duplicates and seven overlaps as candidates.

### Not verified

- The **document move** path (`hodd/reference/`) is exercised only by the guard rails, not
  by a real move: no document in the hoard currently declares `superseded_by:` with an age
  past a year, which is the honest condition for moving one.
- Near-duplicate consolidation is deliberately **report-only**; it has no automated proof
  because a machine-written summary of two memories is an invented fact.
