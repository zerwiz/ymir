## runtime · unversioned · 2026-09-23 — the start path finds `bun` (Smíðja no longer skipped)

### Why
- **Problem (found testing the four menu apps):** `scripts/start.sh` printed
  *"Smíðja visualizer skipped (needs bun + …/visualizer)"* on a machine where
  `bun` **is** installed at `~/.bun/bin/bun` — because it checked
  `command -v bun` against a PATH that never carried `~/.bun/bin`. The installer
  already adopts that directory (`bin/ymir-install.sh`), but the start path and
  the smithy board did not, so the fourth app rode only on a process left running
  from before.
- **Fix:** both `scripts/start.sh` and `bin/smidja-board.sh` adopt
  `$HOME/.bun/bin` once, before their checks:
  ```sh
  if ! command -v bun >/dev/null 2>&1 && [ -x "$HOME/.bun/bin/bun" ]; then
    PATH="$HOME/.bun/bin:$PATH"; export PATH
  fi
  ```
  The Smíðja asset (`assets/smidja.md`) records it as Gotcha 0.

### Verified
- With `~/.bun/bin` **removed** from PATH, `scripts/start.sh` now raises the
  visualizer: *"Smíðja visualizer API raised (pid …) → http://127.0.0.1:8437/"*
  (previously: skipped). All four doors rose in one run.
- The isolated resolver logic finds `bun` (`bun --version` 1.4.2) after adoption.
- `bash -n` clean on both scripts.
