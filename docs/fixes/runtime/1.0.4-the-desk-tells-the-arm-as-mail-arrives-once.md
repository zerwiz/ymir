## The ask

*"Gná: new incoming things — tell to the Gná arm so we can actually act on them as they come?"*

The desk already imported and classified (23 messages, 0 handled). What it never did was **say anything at the moment of arrival** — the Allfather had
to ask "is there anything?" and then a human pass had to be run by hand.

## What was built

| piece | what it does |
|---|---|
| `bin/mail/gna_notify.py --pending` | prints the line the arm *would* be told — a dry run, no writes |
| `bin/mail/gna_notify.py --nudge` | says it into the arm's own queue (`$YMIR_HOME/state/.wake-queue`), under the extensions' lock |
| `bin/time/nornir-job-gna-mail.sh` | after a **successful** import, calls `--nudge`; a failure to tell is a Rune, never silence |
| the notification ledger | `hodd/memory/mail/notified.jsonl` — append-only: which messages the arm has been told about |

## Three faults found while building it, each kept in the record

1. **`seat-wire.sh nudge` is the wrong door.** It refuses its own seat — *"a seat that answers itself is a loop"* — and it names a PEER. The local arm
   queue is written directly, under the lock, in the one-line shape every other raiser uses. **Correct door, and the loop guard is right.**
2. **`direction` is `in`/`out`, not `inbound`/`outbound`.** The first run reported "nothing new" while 15 messages sat unspoken.
3. **A record carrying `notified_at` cannot be appended.** `gna_store._sha` hashes *content only*, so the version hashes identically and the append is
   skipped as unchanged — the first run said **"marked 0"**. The notification ledger is therefore **its own file**: the spine keeps meaning "one line
   per content state", and "was he told?" becomes a separate, honest question.

## Proved, live

- `gna_notify.py --nudge` → `marked 15 version(s) notified`, and the line landed in `state/.wake-queue`.
- **The arm raised it into the session twice**, with the Allfather's own words echoed back — the road works end to end.
- **A second run says nothing:** `gna_notify: nothing new to tell the arm`. No duplicate wake from the desk's side.
- Duplicate queue lines were collapsed by hand once, because the arm raises a line and does not drain it; the flood brake is the arm's own, and
  batching (one line per run, never one per message) is what keeps it fed instead of flooded.

## What this does not do

It does not act. It **tells**. Acting is still `--reply`, `--route`, `handled` — pieces 1–3 of plan 193 §12.2, and that is the next build.
