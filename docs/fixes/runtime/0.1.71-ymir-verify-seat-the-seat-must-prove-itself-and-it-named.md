## Why the test builds a real whole seat

The first version of the test pointed `PI_EXT_DIR` at the **repo root** and so "proved" a whole
seat while the door said the extensions were missing. That is the mocking failure mode wearing a
test's clothes: it would have passed while proving nothing. Now the whole-seat case is a **real**
one — the four extension files deployed, the watch marker present, and a lock naming **this shell**
(so the liveness check is genuine) — and the lock path resolves (`BROKK_STATE_ROOT`) rather than
being hardcoded, because Rule 07 is for tests too.

**7 passed, 0 failed**, and the promise that matters is proved both ways: a whole seat verifies
WHOLE, and a seat missing anything **exits non-zero and names it**.


## The same push also brought the reader for these notes

The range that added `bin/seat/verify-seat.sh` and `scripts/start.sh` also added
**`bin/update-notes.sh`**, because the two are the same law seen from both sides: **a record nothing
reads is not a record.** The door makes the seat prove itself; this one makes an **updating user see
what they received**. A user running `bin/groa-update.sh` had no way to tell what had just landed, or
what to re-check — while every change carried a note in `docs/fixes/` that nobody printed.

Same shape, same failure class, two surfaces:
- a capability silently absent (the watch) → `bin/seat/verify-seat.sh`, non-zero at every app start
- a change silently undelivered to the reader (the notes) → `bin/update-notes.sh`


## Two slips the test caught in the door itself

The suite is not decoration — it found two faults in the door on its first runs:

1. **The door called a resolver it had never defined.** `ymir_home_root` was invoked at top
   level while `bin/vault/hoard-lib.sh` (which defines it) was only sourced inside a subshell. The
   fallback to `$YMIR_HOME` then quietly proved LESS than the door claimed — the same failure as a
   grader that cannot measure. Now the library is sourced at the top.
2. **Liveness was unprovable by a fixture.** `pgrep -f "syn-watch|…"` matched its own command
   line in some shells, so a whole-seat test could never prove itself. `WATCHER_PIDS` now lets a
   fixture pass a **real, alive** pid, and the default is still the real search — injectability
   without weakening the real path.

WHOLE, and a seat missing anything exits non-zero **and names it**.
