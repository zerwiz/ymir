## runtime · 1.4.2 · 2026-10-28 — the well answers on every role

### Why

The Allfather, on his phone: *"this must be built so it works for this device and the fleet."*

`bin/bridge/mimir-bridge.sh --start` was one command with one road. It resolved an interpreter, tried
`import engram`, and — when the import failed — printed `error: engram not installed for python3.13` and
exited 1. On a `hand` that failure is permanent: `engdbram` needs `sqlite-vec` and `fastembed` built for
the device, and Android/Termux has no wheel for either, which `bin/engine/prereq-ensure.sh` already knows
(it prints *"the well is the heart's door here"* and exits 0 — a clean skip). So the installer skipped
correctly, and the runtime then failed every morning: `bin/time/saga-session-start.sh` reported
`well bridge: not up`, `bin/records/mimir.sh` had no door to speak to, and recall/observe were dark on the
one device the operator carries. Rule 25 was satisfied by a skip; the fleet was not served.

### Fix

`bin/bridge/mimir-bridge.sh` now **probes and takes the role's own road**, with one verb:

- **local engine present** → serve it, exactly as before (`well[1]{…,"started"}`);
- **engine not importable** → raise the hand's door (`bin/records/well-door.sh up`, the ssh forward to the
  heart's `:4602` and the MCP face on `:8317`) and, if it answers, report
  `well[1]{port,store,status}: 4602,"door","borrowed from the heart"` and exit 0;
- **engine absent and the door silent** → exit 1 with the *repair*, not a bare skip:
  `no local engine under <py>, and the door to the heart did not answer` / `help: bin/records/well-door.sh status`.

`--status` now names the road that answered — `up (local)` when this box owns the process (pid file alive),
`up (door)` when something else serves the port — because a green that hides a borrow is the false green
this house has paid for twice. `--stop` closes a borrowed door through its own owner
(`well-door.sh down`) instead of leaving an ssh forward standing for a well nobody uses.

No second command, no new flag, no table of devices: the role's road is chosen by what the machine can
actually do, and the path is resolved (Rule 07), not named.

### Evidence

- `.agents/tests/well-door.test.sh` — 6 assertions, all passing on this seat: a borrowed door reports
  `up (door)`; an owned process reports `up (local)`; a silent port reports `down` as a row; no engine and
  no door exits 1 and names both the engine and the repair.
- On this `hand` (Android/Termux, python 3.13, no engram): `--start` now prints
  `well: no local engine under python3.13 — raising the door to the heart`, then either the borrowed row
  or the named failure — never the old dead end.
- The law this serves: RULES/25, its 2026-10-28 appended section (the fleet is the test), and RULES/39
  (the manner and the alarm).
