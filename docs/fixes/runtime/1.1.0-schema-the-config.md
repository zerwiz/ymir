## runtime · 1.1.0 · 2026-09-27 — schema the config: a config the runtime reads refuses loudly, naming the key and the file

### Why

An operator's YAML was a silent contract. A wrong key, a wrong type, or a role the
fleet does not know either did nothing or fell back to a default, so a typo in
`agents.yaml` could seat an Eindri on the wrong model and say nothing. Plan 58,
Phase 7 ends that: the configs the runtime actually resolves are validated against
JSON Schema at load, and a fault is a loud refusal — never a default.

### Fix

- New layer `src/ymir_runtime/config/`: `load.py` (read · parse · validate ·
  semantic checks) and `schema.py` (the JSON Schema refusal, backed by
  `jsonschema`; absence of the validator is itself a refusal, never a downgrade).
- Schemas for the four configs the runtime reads, beside their examples:
  `config/agents.schema.json` · `config/cron.schema.json` ·
  `config/fleet.schema.json` · `config/eindri-dispatch.schema.json`. `cron.yaml`
  is a line format, so the loader parses `HH:MM [@role[…]] <command>` (either
  order) into a document and validates THAT — an unparseable line is a job that
  silently never fired.
- Semantic invariants JSON Schema cannot state: an agent name must be a rostered
  figure (`.agents/agents/` is canonical), and the fleet `heart` must be a
  declared host (a registry naming a host that is not itself is refused when the
  host is known).
- The door `bin/ymir-config-check.sh` (module CLI `python3 -m ymir_runtime.config`,
  so the engine's four-verb interface is unbroken) and a `config` check in
  `.agents/skills/lifecycle/smoke_test.sh` over the shipped shapes.
- `src/pyproject.toml` declares `jsonschema>=4.17` and `PyYAML>=6.0`; the engine's
  venv (`bin/engine/ymir-engine-ensure.sh ensure`) installs them. Version `1.1.0`.
- `.gitignore`: `*.egg-info/` (the editable-install metadata the engine venv
  writes).

```
    fleet.json.example ok · eindri-dispatch.json ok                    exit 0

    "/tmp/proof/agents.yaml: default_model (schema agents.schema.json):
     [1] is not of type 'string'"                                       exit 1

  → refuse: agents.ghostfigure: agent 'ghostfigure' is not a rostered figure  exit 1

(4 hosts) · cron.yaml (11 jobs)                                          exit 0
```

no-validator refusal path is always tested. Under the engine venv
(`~/.fleet/ymir-engine-venv/bin/python -m unittest`): `124 tests, OK` (no skips).
