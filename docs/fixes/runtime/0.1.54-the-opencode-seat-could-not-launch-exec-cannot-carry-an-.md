## runtime · 0.1.54 · 2026-09-29 — the opencode seat could not launch: `exec` cannot carry an env assignment

### Why
Dispatching an errand on the opencode harness died instantly, every time, with:

```
managandr.launch.sh: line 4: exec: OPENCODE_CONFIG_CONTENT={"permission":{"*":"allow"}}: not found
```

The worktree was cut, the seat record written, the brief filed — and the smith never ran.
The cause is the seam between two correct-in-isolation pieces:

- `seat.py`'s launch-script writer prefixes `exec ` to any shape that does not already
  carry it (`elif not launch_cmd.startswith("exec "): inner = f"exec {launch_cmd}"`).
- `harness.py`'s opencode shape **began with an env assignment**:
  `OPENCODE_CONFIG_CONTENT='…' opencode --model … --prompt …`.

`exec NAME=value cmd` is not runnable shell — bash looks for a command literally *named*
`NAME=value`. So every opencode seat on the fleet was dead on arrival, and **pi seats were
never affected**, which is exactly why this survived: the pi shape starts with a command, so
the `exec` prefix is valid there. A seam that only one consumer can survive is not a seam.

The same errand failed a second time for a second, unrelated reason on the way
(`engine-cannot-own: the brief has no # Task section to judge`) — recorded here because the
first failure's real cause was masked by the second, and a half-diagnosed dispatch wastes a
seat.

### Fix
The opencode shape is now **self-contained**:

```python
"env OPENCODE_CONFIG_CONTENT=" + quote('{"permission":{"*":"allow"}}') + f' opencode {model_flag}--prompt …'
```

`env` is load-bearing, not decoration: with it the shape is valid **both** as a plain
command and after `exec `, so no caller can break it again.

### Verified
- `python3 -m unittest discover -s ymir_runtime/tests` → **297 tests, OK (42 skipped)**.
- A NEW guard holds the contract, not the string: `test_every_launch_shape_survives_the_exec_prefix`
  runs `bash -n` over `exec <shape>` **and** over the bare shape for opencode, pi and
  pi-signed. A shape that fails to parse after the prefix now fails the suite — the class of
  bug, not this instance.
- The regression reproduced and repaired on a live errand (`managandr`): after the mend the
  regenerated launch line reads `exec env OPENCODE_CONFIG_CONTENT=… opencode --model …` and
  the seat comes up (herdr pane reports `agent: opencode`).

### Still standing (recorded, not mended here)
- `.agents/skills/syn-recovery/SKILL.md` names `bin/brokk-control.sh <id> relaunch`, which
  **does not exist** on this house: the door is `bin/agents/eindri-control.sh`, and it offers only
  `interrupt | exit | read` — **no relaunch verb**. The real relaunch road is
  `bin/agents/einherjar-spawn.sh <id> --relaunch`, which itself requires the brief at
  `data/<id>/brief.md` to be filled (`bin/agents/erindi-brief.sh <id> --relaunch`). A recovery
  playbook whose commands do not exist costs a recovery.
- A failed seat record blocks a fresh own (`engine-cannot-own: a seat record already
  stands`), and `eindri-control.sh exit` reports "stopped" without clearing it, so the
  stale launch script is reused and the errand cannot be re-forged. Cleared by hand after
  backing up, this time — with the worktree proven pristine first.
