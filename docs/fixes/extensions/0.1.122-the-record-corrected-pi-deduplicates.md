# 0.1.122 — the record corrected: pi DOES de-duplicate its extension paths

The fix note for 0.1.120 first claimed six identical `extensions[]` entries loaded the tree six
times, and that this multiplied every warning. **It was wrong, and the loader was the witness:**

```js
// dist/core/extensions/loader.js:666-673
const seen = new Set();
const addPaths = (paths) => { for (const p of paths) {
  const resolved = path.resolve(p);
  if (!seen.has(resolved)) { seen.add(resolved); allPaths.push(p); } } };
```

Identical strings resolve to the same path and load **once**. So the duplicated array was not the
cause of the flood — the raw multi-line `console.warn` was, and the notice gate is the fix.

The duplicate was still a fault: a differently spelled path to the same tree (a symlink, a trailing
slash, a second checkout) resolves differently and **does** double-register every tool. That was seen
first-hand on this branch, where the worktree tree and the settings entry both loaded:
`Tool "ymir_recall" conflicts with …`. `valknut-load.sh` now refuses to write a duplicate and
`--check` fails on one; the claim in the note and in `harness-integration/pi.md` was corrected
rather than left standing.

> A claim that a measurement does not support is not a fix note. Correct it in the record, in the
> same breath, and say which witness proved it.
