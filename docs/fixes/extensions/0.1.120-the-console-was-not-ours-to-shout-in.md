# 0.1.120 — the console was not ours to shout in: the notice gate, and the duplicate that multiplied it

> The Allfather: *"im getteing alot of error codes in to pis session at the bottom they are spilling
> over where im typing. some warning syatem are not confiured rigth.. someting that says requirestack
> livesessions etc etc"* — then: *"we need to hadle this errors better. they are breaking the ui in pi.
> both on phone and computers"*.

## What the measurement showed

```
~/.pi/agent/settings.json  extensions[]  →  the SAME tree named SIX times
pi                         does NOT de-duplicate extensions[]
```

`bin/seat/valknut-load.sh` ended its settings merge with

```python
kept = [entry for entry in extensions if not is_other_ymir_extensions(entry)]
kept.append(src)          # ← unconditional
```

so **every run added another copy**. Six runs, six copies, and pi loaded the whole
extension tree six times: every tool registered six times, and every extension's console
warning printed six times.

The warnings themselves came from `pi-hermes-memory` on the phone:

```
⚠️ Live session indexing failed: dlopen failed: library "libstdc++.so.6" not found …
⚠️ Live session indexing failed: <same, once per message_end>
```

Five lines of `Require stack:`-shaped native text, twice a turn, six times over — written
with `console.warn` straight at the terminal the TUI has taken over. That is the paint over
the editor.

> **A warning is not a design decision.** Pi's channel for this is `ctx.ui.notify()` /
> `ctx.ui.setStatus()`, which redraw cleanly; a foreign package uses neither, and the host
> cannot ask it to.

## The fix — two faults, two answers

**The duplicate.** `valknut-load.sh` now de-duplicates the whole array (first-seen order kept,
a repeated path dropped) and only appends the tree when it is absent. It also *heals* an
already-corrupted list. `--check` now fails on a duplicated entry, not merely on a missing one,
so the drift cannot come back silently.

**The flood.** `.pi/extensions/nidhogg-notice-gate.ts` — **Níðhöggr**, the loop-breaker, turned
on the noise. Installed when the extension loads, it wraps `console.warn`/`console.error`:

| rule | behaviour |
|---|---|
| one line | a multi-line message is reported by its first line + `(+N lines — see state/pi-notices.log)` |
| one time | the same message is shown once per session; repeats are counted (the log records `seen Nx`) |
| the whole record | the untouched text is appended to `<state>/pi-notices.log` — suppressed is not lost |
| no UI, no gate | print/JSON/RPC have no TUI to protect, so the collapsed line is passed through, once |

The gate is installed once per process (a `Symbol.for` flag), so even a duplicated load path
cannot stack two of them.

Measured after (phone, print mode):

```
before   ⚠️ Live session indexing failed: dlopen failed: library "libstdc++.so.6" not found …
         <4 more lines>          ← then again, per message_end
after    ⚠️ Live session indexing failed: Cannot find module '…better_sqlite3.node'
         (+4 lines — see state/pi-notices.log)
```

## What this does NOT do

- It does not make `better-sqlite3` load on Termux. The native module needs
  `libstdc++.so.6`, which Termux does not ship; live session indexing stays off on the
  phone and the log says so once. The *UI* is the thing fixed here.
- It cannot catch pi's own `Failed to load extension` errors: a gate that failed to load
  is not running. Those lines are pi's and appear once per conflicting tool — which is
  exactly the symptom the duplicate fix removes.

## Verified

- settings merge run three times → `added`, `unchanged`, `unchanged`; seeded with four
  entries (three of them the same tree) → healed to one.
- gate loaded under `pi --extension ./gate.ts -p "say ok"` → the native failure printed as
  **one** line with the `(+4 lines …)` suffix, and the second occurrence was silent.
