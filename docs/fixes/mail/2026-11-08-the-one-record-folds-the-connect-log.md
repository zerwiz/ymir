# The one mail record now folds the connect log

**Component** `mail` · **Date** 2026-11-08 · **Plan** 221 (the connect door)

## What was wrong

The connect door (`bin/mail/connect.sh`) kept its own append-only event log,
`hodd/memory/mail/connect-log.jsonl`, beside the mail ledger, `hodd/memory/mail/ledger.jsonl`. Both live in
the same directory and both are appended to and never rewritten — but `bin/mail/ledger.sh tail` read only
the ledger and the desk's store. So the house could show the letters and silently hide that a grant had been
made or revoked. A door that opened and closed left no trace in the one place a person looks.

That is the same fault as a green service on the wrong port: the record existed, in a file nobody read.

## What changed

`bin/mail/ledger.sh tail` now folds the connect door's log into the one view, read-only. The connect event
appears as a row with direction `connect` (a grant made) or `revoke` (a grant removed), the account in the
"who" column, and the verb's result in the subject column.

The two files stay separate on disk. They are written by different hands, each is append-only under Rule 06,
and merging them into one file would mean a second writer to a record that is only safe because each append
is atomic. **The reading is what is shared, not the file.**

Nothing was forked: this is nine lines in the door that already owns the view, plus a self-test line.

## Proof

```
$ bin/mail/ledger.sh self-test
ok   : two rows appended, none rewritten
ok   : a quote in a subject cannot break a row
ok   : the connect log appears in the one view
ok   : the ledger is append-only by construction (the door has no edit verb)
ledger-self-test: pass
```

The new assertion writes a fixture connect row and fails if `tail` cannot see it — so the fold cannot rot
back into invisibility without a red line.

Re-run after the change, on this seat:

```
$ bin/mail/connect.sh --self-test          → result: PASS — 25/25 for all
$ bin/mail/connect.sh google --self-test   → 16/16
$ bin/mail/connect.sh imap --self-test     → 6/6
$ bin/mail/connect.sh status --self-test   → 5/5
$ bin/mail/connect.sh revoke --self-test   → 7/7
$ bin/mail/addresses.sh --self-test        → 10/10
$ python3 bin/mail/tests/test_gna.py       → 37 tests, OK
```

## Also recorded here

The branch was 24 commits behind `main` when this landed, so it was merged forward: `bin/mail/ledger.sh` did
not exist when the connect door was first written, and a door cannot extend a record it cannot see. The merge
brought `main`'s desktop, gates, time and letter-template work in with it; the woven documents (`bin/*/INDEX.md`,
`FEATURES.md`) were regenerated by `bin/gates/inventory.sh` and `bin/records/weave-features.sh` rather than
hand-merged, because a woven document has no hand-kept content.
