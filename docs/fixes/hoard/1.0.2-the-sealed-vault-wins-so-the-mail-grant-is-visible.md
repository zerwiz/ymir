## The fault, measured 2026-11-05

`bin/vault/hodd-set.sh` writes `secrets/platform.env.age` and **nothing else**. `bin/vault/hodd.sh emit` preferred the **plaintext**, so a plaintext
left beside the sealed file went stale in silence.

The cost was real and it was not subtle: the mail grant (`GOOGLE_MCP_CLIENT_ID`, `GOOGLE_MCP_CLIENT_SECRET`, `SNOTRA_GOOGLE_REFRESH_TOKEN`) was
written into the `.age` and **every reader still saw 74 keys without it**, so `gna` reported *"credentials missing"* while the vault held them, and
the mail import failed on every run since 2026-11-03 — on both seats.

## The change

`resolve_secret` now tries the **`.age` first** and uses it when it decrypts to something non-empty. The plaintext is the fallback, and the older
rule still holds inside it — an empty plaintext never shadows the vault (the 2026-09-23 fault).

## Proved

- `bin/vault/hodd.sh emit secrets/platform.env | wc -l` → **77 keys** (was 74), and the three Google keys now appear.
- `bin/time/nornir-job-gna-mail.sh import` → **read 23, store 23 written**, `rc=0`; before the change, `rc=1` with *"credentials missing"*.
- `/health` → `accounts: ["<the operator's own mailbox>"], messages: 23, versions: 23, last_ingest 2026-11-05T18:02Z`
  (the address is masked here on purpose — RULES/04: the public tree carries no personal mailbox).
