## forge · 1.2.0 · 2026-11-06 — the box had no one in it

### What

**The fault, said plainly:** a box installed `pi` and nothing to be. There was no `~/.pi/agent` tree at all — no agents,
no skills, no commands. So "the utgard agents do not work" was not a bug in a proxy or a lane: there were **no agents in
the box**. Measured before the fix: `ls ~/.pi/agent/agents` inside a fresh box printed nothing.

**The harness is now seated at birth.** `utgard box new` seats the seat's own harness into the container — the agent
files, the skills, the commands — and the project's shipped skill shelf at `/box/work/.agents/skills`, where an agent
inside the box looks for it by the same rule it uses on the host. On this seat that is **24 agent files, 3 harness skills
and 32 project skills**.

- **`utgard box harness <name> [--from DIR] [--skills DIR]`** seats it again, or seats a different harness — a different
  home, a checkout, a client's own. `--no-harness` makes a deliberately bare box.
- **A copy through a tar, never `docker cp` and never a mount.** `docker cp` writes as root, so the agent could read its
  own harness and never replace it; a mount would let it write home. The tar arrives as the agent, owned by the agent.
- **Never a fetch.** A box sealed to one road cannot reach a git forge, so the harness it runs is the harness that was
  put in — which also means a lane's harness is an axis that can be varied deliberately rather than a thing that drifts.
