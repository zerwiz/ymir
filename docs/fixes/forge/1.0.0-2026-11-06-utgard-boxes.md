## forge · 1.0.0 · 2026-11-06 — Utgard grows a workshop: a whole computer per run, and a door that holds the key

### What

`bin/forge/utgard.sh run` is a **locker**: `--rm`, read-only rootfs, no network, 1.0 CPU, 512m, thirty seconds. That is
the right instrument for one untrusted command, and it is why a routine agent run had **the operator's whole machine as
its blast radius** — sharing `$HOME`, the git identity and the rail key. Smíðja's own `permissions.py` said so in one
line: *"'tools:' is a capability list, not a sandbox"*.

This adds the missing floor:

- **`bin/forge/utgard-box.sh`** — `utgard box new|list|status|enter|url|seal|pull|stop|start|rm|gc|build|probe`. A box is
  a durable named container with its own writable layer, its own volume at `/box`, its own network, its own TTL labels,
  and a published loopback port. It is entered while it runs, and its harvest is pulled out by `docker cp` — a copy,
  never a mount, so nothing inside can write home.
- **`bin/forge/utgard-box-door.py`** — the box's **one road**. A plain HTTP proxy with an allowlist of *names*, where a
  name has no meaning outside the door (`rail` → wherever the rail actually is). It **injects the rail credential**, so a
  box holds the word `door` where the key would be and nothing worth stealing. Anything not on the list is
  refused **in words**: `door: no road to 'example.com'. The box reaches only: rail.`
- **`.agents/sandbox/Dockerfile.box`** — Debian slim (musl breaks `pi`'s native deps), node 20, python3, git, `pi`,
  one unprivileged `agent` user, `tini` as entrypoint. Built as `utgard-box:latest`.
- **`bin/forge/utgard.sh box …`** dispatches to it, so there is still one Utgard.

Three laws are enforced rather than advertised: no host credentials (no `$HOME`, no vault, no ssh key, no rail key), one
road out (the door), and a box is a record (labelled, timed, listed, reclaimed by `gc`).

**The seal is MEASURED, not remembered.** Docker labels are immutable once a container exists, so `box seal` re-shapes
the network attachments and then reads the seal back off the kernel's view: on its own internal net + a door → `door`; on
the ordinary bridge → `open`; on nothing → `none`.

### The fault found on the way, and it is bigger than boxes

A container on this host **cannot reach any service on the host at all** — not :22, not :8080, not a scratch listener on
a fresh port. Measured, not inferred: the door dials the host's own bridge address on the rail's port and hangs, while it reaches a
stub on its own bridge instantly. The cause is the host's firewall: `ufw` is active and `DEFAULT_INPUT_POLICY="DROP"`
(`/etc/default/ufw`), and container→host traffic is INPUT, which Docker's own rules do not open.

So the doors now share **one named network with a fixed subnet** (`utgard-door-net`, the subnet from
`UTGARD_BOX_DOOR_SUBNET`), and `box new`, `box seal` and `box probe` print the exact one-line rule that opens that road
and nothing else. The line is printed with the real numbers at run time; this note does not carry them, because a
document in a public repo does not carry an address (RULES/39) and `public-data-guard` says so.

It is **printed, never applied**: the ward is the operator's (RULES/24), and a script that silently widens a firewall is
the class of fault this house keeps paying for. Until the rule exists, `box probe` reports the rail law as FAIL and names
the remedy — a refusal that names the road, never a silent downgrade.

Also fixed here: `fixes-guard`'s `path_component()` knew no `bin/forge/*` shape, so a correct forge note could never
cover a forge path and the gate could only warn. One row added.

### Verified

- `bash tests/test_utgard_box.sh` — **29 pass, 0 fail, 0 skip** against a live Docker engine, using a stub upstream so
  the suite never touches the real rail. Proved: the box's `HOME` is its own, the operator's home is not visible and no
  host path is mounted, the real key is in no env var, the rail answers **through the door** and the stub saw
  `Authorization: Bearer <the door's key>`, `example.com` is refused *in words*, `list`/`url`/`pull` work, and duplicate
  names, invalid names, sub-five-minute TTLs and absent boxes are all refused.
- A clean skip is a pass (RULES/25): no engine, no daemon, or no image each exit 0 with the reason and the command that
  fixes it.
- `bin/forge/utgard.sh box probe` — on this host today: no host home **PASS**, no other road **PASS**, no credential
  **PASS**, rail **FAIL** with the ufw remedy printed (the rule above is owed by the operator).
- The box image builds in 1m45s (`utgard-box:latest`, `sha256:83151ef4…`).
