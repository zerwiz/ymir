# forge · 2026-11-18 — a rendered file is not a record

## Files

- `bin/forge/review-mend.sh` — the mechanical change-log rung skips a file that says it is generated

## Why

The mechanical rung looks at every changed `.md` in a pull request and appends a `## CHANGE LOG`
block when the file has none. That is a reasonable rung for a record written by a hand. It is
wrong for a file a script renders: `.agents/assets/agents/capabilities.md` declares itself in its
own head — *"GENERATED by `bin/gates/capabilities.sh`. Do not hand-edit"* — and every render
rewrites it from the tree, deleting the block.

The two therefore disagreed for ever. PR #817 collected **eighteen** commits all titled
`judge: change-log for #817`, each re-adding the same four lines, and the `capability` gate stayed
red through every one of them because the register it compared against had just been rendered
without them. A mend loop that cannot converge spends the gate's runs and the operator's night.

## Fix

Before appending, the rung reads the first fifteen lines of the file. A file that says
`generated by …` or `Do not hand-edit` is skipped with a printed reason: its renderer owns it, so
the change belongs in the tree the renderer reads, never in its output.

The register itself is regenerated in the same change (`bin/gates/capabilities.sh`), so the red
this loop was chasing is gone rather than papered over.
