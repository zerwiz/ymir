## install · 0.1.0 · 2026-10-19 — the ear's runners deploy from their shelves

### Why
`bin/fleet/fleet-ensure.sh` deploys the meeting ear's operator commands into
`~/.fleet/` so any seat runs them without a repo checkout on its PATH. Since the
**2026-09-20 reorganization** those scripts live on their own shelves
(`bin/time/snotra/…`, `bin/vault/hoard-lib.sh`, `bin/records/runes-append.sh`) —
but the deploy step still read the flat pre-move path `$ROOT/bin/<name>.sh`. Every
one of them silently failed to copy (no copies, no error), so a unit whose
`ExecStart` is `%h/.fleet/snotra-detect.sh run` failed `status=203/EXEC`: the
runner was never there. Found on the Steam Deck (aegir) 2026-10-19 — the ear only
rose after the files were placed by hand.

### The fix
- Resolve each file where it now lives (`bin/time/snotra/…`, `bin/vault/…`,
  `bin/records/…`) and deploy it under its bare name in `~/.fleet/` — the same
  names the units and the other runners expect.
- `snotra-live.sh` is added to the set (it is part of the ear and was never in it).

### Also in this change
- `bin/time/snotra/snotra-ensure.sh` — the seat-name fallback chain
  (`hostname -s || hostname`) had no final alternative. **SteamOS ships no
  `hostname` binary**, so it printed `hostname: command not found`. The chain now
  ends `hostnamectl --static || printf seat`, which answers on SteamOS and never
  empties.

### Verified
On the deck: after deploying by hand, `snotra-ensure.sh status` names the engine
and the model, `snotra-detect.service` is **active**, and `fleet-ensure.sh ensure`
reports *every role-owed program is enabled and standing*.
