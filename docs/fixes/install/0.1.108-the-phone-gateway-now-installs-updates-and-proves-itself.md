# 0.1.108 — the phone gateway installs, updates, and proves itself

> *"we need to make some smoke test scripts for this and also make this work on installation and
> updates for ymir."*

A capability that is committed but never seated is the exact failure `bin/engine/ymir-install.sh` already
refuses for extensions ("a seat that cannot be seated is not installed"). **The gateway is now held to
the same rule.**

## `tools/ymir-gateway/smoke.sh` — safe by default, because it had to be

The earlier smoke test I wrote called every tool with `{}` and wrote **28 junk plans and 28 junk
memories into the operator's vault** (0.1.105). A test that can damage something is not a test. So:

```
parse:session.mjs        PASS
parse:acp.mjs            PASS
parse:pi.mjs             PASS
session-identity         PASS      12 checks, no network, no agent
brains-offline           PASS      10 checks, both brains, one seam
brains-live              SKIP      not asked for (YMIR_LIVE=1)
acp-sdk                  PASS      the dependency we adopted on purpose
```

- **Offline by default.** No network, no agent, no model — so a gate can run it anywhere.
- **Writes nothing outside its own directory.**
- **`YMIR_LIVE=1`** additionally proves the *real* rail answers — and the key is read **by
  reference** from the seat's auth file. Never printed, never written, never committed.
- An absent key is a **SKIP with the reason printed**, not a silent pass and not a failure.

## Local models work, and are proven

`pi.mjs` — the local brain on the llama rail — and `pickBrain()`:

```
auto prefers LOCAL when the rail answers      (privacy by default)
auto falls back to hosted when there is none  (and says so)
asking for local with no rail REFUSES         ← it does NOT silently go to the cloud
```

That last one is the assertion I care about most: **a silent cloud fallback is the failure this
guards against**, because it would look like success and send a private conversation to a server.

**Live, against the real rail on this box:** `11 passed, 0 failed`.

## And the bug this wiring immediately exposed

`groa-update.sh` set `GATEWAY_FAILED=1` and **nothing read it** — the update printed a warning and
exited 0. That is *precisely* tonight's disease in new clothes: a check that reports and does not
fail. Fixed:

```bash
exit "$(( ${seat_failed:-0} || ${GATEWAY_FAILED:-0} ))"
```

It was caught by asking the only question that matters about a new gate — **"what happens if this
fails?"** — and following the flag to where it was supposed to matter.
