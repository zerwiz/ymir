# 0.1.115 — the root pointer carried two dead worktrees

`~/.pi/agent/extensions/.ymir-root` is the list every extension resolver reads:
`$YMIR_ROOT`, else **the first recorded root that really holds `bin/syn-watch-arm.sh`**. It is a
cache of places that used to be real.

Measured 2026-10-04: **FOUR roots recorded, TWO of them dead** —

```
/yggdrasil/forseti-review-spine   DEAD   (worktree gone)
/yggdrasil/declare-agents        DEAD   (worktree gone)
```

**A cache of dead places is worse than no cache.** Every door an extension reaches through a
recorded root is one failing call away, and the failure is `127` at exec — which is exactly what
the smoke suite reported before:

```
LOAD FAILED  Cannot find module ".../.yggdrasil/pi-ext-la..."      before
             9 called · 17 verified · 1 broken · 1 skipped
after       9 called · 17 verified · 0 broken · 2 skipped
```

## The fix

`ymir_root_record` re-appended every line it found. It now keeps a recorded root **only while it
still is one**:

```bash
[ -x "$line/bin/syn-watch-arm.sh" ] || continue
```

Verified: four roots → **two**, both ALIVE, and the smoke suite goes to **0 broken** without
having to force a module path — which it could not do before.

## The same shape, one level up

This is the lock file all over again (0.1.106): a live-looking artefact that points somewhere dead,
so it satisfies a check and fails the work. A record is only evidence of a thing **while the thing
exists** — and a cache must be pruned by whoever writes it, not by whoever notices.
