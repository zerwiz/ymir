## install · 0.1.75 · 2026-10-02 — install and update now FAIL when the seat cannot be seated

### Files
- `bin/ymir-install.sh`
- `bin/groa-update.sh`

## The rule, and where it was being broken

> plan 66 §7: **a feature is not done when its code exists** — it is done when the install seats it
> for a fresh seat and the update brings it to an existing one.

Both scripts already called `valknut-load.sh`. **Both then carried on when it failed**: the install
recorded a `WARN`, and the update printed a warning and exited 0. That is precisely the fault that
cost us the watch on 2026-09-30 — an extension fix merged, the tree moved, and the seat was never
seated, and nothing failed.

**Now:**
- `bin/ymir-install.sh` — the loaders step is a **FAIL**, and a failed step fails the install.
- `bin/groa-update.sh` — seating failure prints **FAIL — this update is NOT complete**, sets a flag,
  and the flag **reaches the exit code** (`exit 1`), so a caller — Gróa's skill, CI, a human —
  can *see* that the seat is behind its own tree. Pointed at `bin/seat/verify-seat.sh`, the door added in
  0.1.71, which is the same claim turned into a check.

**Verified:** `ymir-install.sh --check` reports `loaders OK`; both scripts parse; the tree wards
pass. The failure path is not exercised here because provoking it means breaking the seat on
purpose — and `bin/seat/verify-seat.sh` exists precisely so that need not be simulated.
