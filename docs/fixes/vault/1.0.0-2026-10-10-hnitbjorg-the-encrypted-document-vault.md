## vault · 1.0.0 · 2026-10-10 — Hnitbjörg: the encrypted document vault rides the install

### What

A new subsystem, **Hnitbjörg** (`bin/vault/hnitbjorg.sh`): a LUKS2 container for
the operator's private documents, **sealed by default**, opened only with `sudo`
and a passphrase that is never stored. Adds:

- `bin/vault/hnitbjorg.sh` — the door (`init · open · close · status · backup ·
  passwd · fido2-enroll · fido2-list`), paths resolved through
  `bin/vault/hoard-lib.sh` (Rule 07).
- `bin/vault/hnitbjorg-ensure.sh` — the surface (cryptsetup + vault dir); never
  creates a vault.
- `bin/engine/ymir-install.sh` — a `step_vault` that ensures the tooling and
  offers `init`, never runs it.
- `bin/agents/eir-doctor.sh` — the `vault` surface; a sealed vault is healthy.
- `.agents/skills/galdr-ymirsystem/assets/vault.md` + router/asset registrations.
- `.agents/assets/agents/naming.md` — the Hnitbjörg row.
- `tests/e2e/vault-proof.sh` — the offline contract proof.

### Why

The Allfather asked for a secure vault for documentation that is encrypted and
unreachable to agents or humans without access, reachable across his fleet.
Encryption protects at rest and while **unmounted**; while mounted, any process
as the operator (agents included) can read it — so the vault is sealed by
default and closed by hand. Plan 72 holds the reasoning.

### Verified

- `tests/e2e/vault-proof.sh` — all assertions pass offline (version/help fast
  paths; sealed-by-default `status`; `open` refuses with no vault; `init` refuses
  to overwrite; ensure status).
- `bash -n` clean on all touched scripts; `hnitbjorg.sh --version` = 1.0.0.
- `cryptsetup 2.8.7` present; `systemd-cryptenroll` on this host has **no
  `--header` support**, so the container uses an **embedded** LUKS header (the
  reason detached headers were dropped — FIDO2 needs it).
