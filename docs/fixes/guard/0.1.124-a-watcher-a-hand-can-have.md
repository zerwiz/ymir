# 0.1.124 — a watcher a hand can actually have, and a ward that stopped lying green

## What the measurement showed

`bin/ward/security-audit.sh` on the phone:

```
"HIGH","sshd accepts PASSWORDS","…","keys only: a drop-in with 'PasswordAuthentication no' …"
"HIGH","nothing watches this host","no fail2ban/crowdsec/lynis/aide/osquery/falco installed","…"
```

The first was real and was mended by hand: a drop-in
(`$PREFIX/etc/ssh/sshd_config.d/99-ymir-keys-only.conf`) with `PasswordAuthentication no`,
`KbdInteractiveAuthentication no`, `PermitRootLogin no`; `sshd -T` confirms all three, `sshd` was
raised, and a **key login was proved before the drop-in was declared good** (the seat's own key
was missing from `authorized_keys` and was added — otherwise the change would have locked the
hand out of itself).

The second finding was true in the letter and useless in the spirit: **no root, no systemd, no
syslog on Android**, so not one of those watchers can exist. The honest question is whether
*anything* looks at the host on a cycle and leaves a record.

## The fix

`bin/ward/host-watch.sh` — the house watcher:

| look | what it records |
|---|---|
| listeners | every bound TCP port, and which are bound to the world |
| doors | sha256 of `authorized_keys`, `sshd_config`, and `sshd_config.d/*.conf` |
| attempts | failed SSH authentications, from `logcat -s sshd` or an sshd log — **or says it could not measure**, never a false zero |

`run` appends one dated block to `<state>/ward/host-watch.log` and refreshes
`host-watch.last`; `status` passes while the last look is under 26 hours old.
`security-audit.sh` now accepts it — and names it — instead of demanding fail2ban.

**The measurement that mattered most here:** Android denies `ss` its netlink socket and
`netstat` refuses `AF INET`, and `/proc/net/tcp` is unreadable. An empty table would have read
as *"nothing is listening"* — the same false-green the well surface had. The watcher therefore
prints **"listeners unmeasured — the kernel table is denied to this app"**, and
`world_bound` says `unmeasured`, never blank.

A cron row was added in the private home (`06:50 bin/ward/host-watch.sh run`, any role), so the
heartbeat stays fresh without systemd.

## Verified

```
before: security-audit → 2 HIGH (sshd passwords · nothing watches this host)
after : sshd -T → passwordauthentication no, kbdinteractiveauthentication no, permitrootlogin no
        ssh -p 8022 127.0.0.1 → key-login-ok
        host-watch.sh run    → recorded
        host-watch.sh status → last look 0h ago
        security-audit.sh check → "none","","nothing above the floor"
```
