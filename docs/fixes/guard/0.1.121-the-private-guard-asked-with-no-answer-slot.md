# 0.1.121 — the private guard asked a question with no answer slot: `ymir_home_root` takes a result variable

## What the measurement showed

Every `git commit` in this repo died before writing anything:

```
File "bin/gates/guards/private-guard.py", line 10, in ymir_home
subprocess.CalledProcessError: Command '['bash', '-c', '. "…/bin/vault/hoard-lib.sh"; ymir_home_root']'
  returned non-zero exit status 2
```

`hoard-lib.sh` defines `ymir_home_root <result-var>` — it **writes into a variable the caller
names** and returns 2 when there is none, because a path is not a return value in a shell
function. Two Python doors still called it bare, exactly as the retired signature allowed:

```
bin/gates/guards/private-guard.py:10
bin/time/snotra/snotra-trello.py:26   (and :253)
```

Every other caller already had it right — `bin/ward/garmr/common.py`,
`bin/assistant/paths.py`, `bin/assistant/skirnir.py` all do `out=""; ymir_home_root out`.

> **It only failed where `YMIR_HOME` was not exported.** With the variable set the function
> returns early and the missing argument never shows. So the guard worked for whoever had the
> env and blocked the commit of whoever did not — the phone, and any fresh seat.

## The fix

Both doors now pass a variable and print it, falling back to the documented default
(`~/Documents/ymirhome`) when the home cannot be resolved at all — a commit is not the place
to enforce the home's existence; the `hoard` surface of `bin/agents/eir-doctor.sh` is.

```python
out = subprocess.check_output(['bash', '-c',
    f'. "{root}/bin/vault/hoard-lib.sh" >/dev/null 2>&1; out=""; ymir_home_root out; printf "%s" "$out"']).decode().strip()
```

## Verified

- `private-guard.py` loaded with `YMIR_HOME` unset → resolves `~/ymir-home` (the recorded
  choice), and a commit on this branch proceeds.
