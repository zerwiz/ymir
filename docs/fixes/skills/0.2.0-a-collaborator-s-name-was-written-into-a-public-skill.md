## skills · 0.2.0 · 2026-11-03 — A collaborator's name was written into a public skill

### Why
Rule 04 and Rule 39: the constellation section added to the ratatoskr skill named a real collaborator of the house, in a repository that is public. Corrected to a generic phrase; the name stays in the hoard.

### Files
- `.agents/skills/ratatoskr-a2a/SKILL.md`
### The fault

The constellation section added to `.agents/skills/ratatoskr-a2a/SKILL.md` in the same change named a real
collaborator of the house — *"Sebastian's, say, with its own hoard, gate and law"* — in a repository that is
**public**. A person's name is private data (Rule 04), and naming a counterpart in a public file is exactly the
class of leak Rule 39's manner is meant to prevent; the house had already paid for it once on 2026-11-03
(plan 171, public fix notes naming the operator).

### What changed

The sentence reads *"a collaborator's house, say"*. Nothing else changed: the section still explains why two
fleets keep two laws, and the example keeps its point without carrying a person. The name lives where it
belongs — `hodd/identity/collaborators.yaml` and the plan ledger, in the private home.

### What the guards said

`identity-guard` and `private-guard` are clean on this branch, and `bin/gates/guards.sh` is 20/20 PASS. The
lesson is the one the rule exists for: a name is easy to type into prose because prose reads better with one,
and no syntax check will ever flag it. Only the ward that knows which words are private can — and it can only
know them if the list is maintained.
