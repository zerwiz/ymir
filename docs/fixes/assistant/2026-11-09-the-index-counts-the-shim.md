# The index counts the shim's lines

**Date:** 2026-11-09 · **Component:** assistant · **Status:** corrected

## Why

`bin/assistant/INDEX.md` is generated by `bin/gates/inventory.sh` and records, per door, its verdict and
its **line count**. Adding the `allow-superseded-path:` waiver to
`bin/assistant/assistant-brief.sh` made that file one line longer — 18 → 19 — in a commit made *after*
the one that regenerated the index. The register was therefore stale by its own next commit, and the
`inventory` gate in CI said so:

```
inventory --check: bin/assistant/INDEX.md is STALE — run bin/gates/inventory.sh
```

## The correction

Regenerated (`bin/gates/inventory.sh`) and committed. Nothing else moved: the door had already been read
`wired · keep`, which is the register's answer to the "unnamed and untested" verdict it gave before the
door was in the tree.

## The lesson, small but real

A generated register records a file's SIZE, so any later edit to a registered door must re-run the
generator **in the same commit** — otherwise the last commit of a branch is always the one that makes the
index stale. Regenerate last, then commit.
