| Gate | **Can anyone mail us? — the address register, the honesty line, and the acceptance test** (`bin/mail/addresses.sh` · `bin/mail/gna_addresses.py` · `bin/mail/inbound-test.sh` · `bin/mail/gna_desk.py --honesty` · `GET /addresses`) | Plan 116 §15.3 asked four questions the desk could not answer, and measured the answer the hard way on 2026-10-24: `zerwiz.org` publishes **no MX at all**, so `gimle@`, `snotra@`, `reply+*` and `bounce+*` there could not receive anything, while the desk showed an empty inbox that looked exactly like "no mail today". `addresses.sh` is the register of the addresses the house **uses** — MX measured over DNS by the resolver's own query (no `dig`; `$GNA_DNS_SERVER` else `/etc/resolv.conf`), routing **declared** in the home's `accounts.yaml` under `house:` (explicit · catch-all · none), arrival **proven** by a proof line only `inbound-test.sh` writes — and `--check` exits nonzero when any declared address is undeliverable, 3 when reachable-but-unproven, 2 when the register cannot be read. `inbound-test.sh` asks first (MX, route, and the Workspace alias through the account's read-only `sendAs` settings), skips with the exact missing record and exit 3 when the world is not ready, and otherwise sends from an **outside** domain through the approved send door and asserts the arrival's `To:` header came through intact. The desk's honesty line adds, per address, `deliverable · forwarded · unreadable` plus an `inbox_state` per account (`arrivable` · `declared-only` · `cannot-arrive`) so an empty queue can never again read as "no mail".
