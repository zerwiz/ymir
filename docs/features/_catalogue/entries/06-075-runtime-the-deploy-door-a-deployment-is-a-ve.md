| Runtime | **The deploy door — a deployment is a version, not a copy** (`bin/gimle/deploy.sh` · [how-to](docs/features/gimle-the-hall.md)) | The Gimlé suite was deployed to the heart by copying files, and `/home/zerwizserver/gimle` was not a checkout — so the running desk came to be *newer* than the tree (membership gate, board section, a Plane reader the tree lacked), with `.bak-` files for history. One verb now closes both directions: the default action moves a clean checkout to `origin/<branch>`, **links** the four code files into the run directory (the private `etc/` tokens and `data/` records are never touched, so a deploy cannot overwrite a secret or a record), refuses to restart if any file will not parse, restarts the three units, and then **proves each door by what it answers** — `:8487 /`, `:8489 /health`, `:8490 /health` each `200` and each unit `active`, a door that fails failing the deploy even when systemd says green. `--check` prints `deployed <running> <merged>` or `STALE` with both commits and exits nonzero when they differ, changing nothing. Agnostic by construction: the same verb acts locally where the units run and over `GIMLE_DESK_SSH` otherwise, a seat with neither SKIPs with its reason, and the paths are resolved **on the machine that runs the units** so `$HOME` means that machine's home — the first draft reused `GIMLE_DESK_DIR`, which names the desk's data shelf, and reported "no checkout" on a host that had one. Measured: `deployed 1476cf57 1476cf57`, three doors answered 200, and the desk renders the Book tile and `card(s) assigned` from the board through the same deploy | [docs/fixes/gimle/2026-11-02-the-deploy-door.md](docs/fixes/gimle/2026-11-02-the-deploy-door.md) |
