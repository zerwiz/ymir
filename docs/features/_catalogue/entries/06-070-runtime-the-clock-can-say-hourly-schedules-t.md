| Runtime | **The clock can say hourly — schedules that repeat, not just land** (`bin/time/nornir-cron-start.sh` · `config/cron.schema.json` · `.agents/tests/nornir-schedule-shapes.test.sh` · [how-to](docs/features/the-clock-can-say-hourly.md)) | The Allfather asked for an hourly memory sync and Nornir could not say it: the matcher was an exact `date +%H:%M` compare with a **per-day** stamp, so hourly meant 24 hand-written rows, and a token it could not read was skipped **silently** while still counting as declared (the 2026-09-24 fault one layer down). Four shapes now parse — `HH:MM` (once a day), `@daily`, `@hourly`, `@hourly:MM` — and the shape decides both the match and the stamp key, so a per-hour row fires once an hour and a per-day row once a day. One parser (`parse_line`/`is_role`/`at_valid`, exported) serves both the loop and the start-time warning; an unreadable shape is named aloud and recorded in `state/.cron-invalid`, which `--status` counts as `invalid=<n>`; the role gate parses before or after a shape. Fields are taken by expansion, never by `read` (this seat put a whole line in the first field under `IFS=<tab> read`). 16 assertions pass against a fake clock; the live 31-row schedule parses clean with no change in behaviour | plan 140 |
