| Mail | **Connect an account — one sign-in, or three fields** (`bin/mail/connect.sh` · `bin/mail/gna_connect.py` · [how-to](docs/features/connect-the-mail-and-calendar-door.md)) | Plan 221's complaint was not the protocol but **authentication onboarding**: a new user needed a Cloud project, three API enablements and three pasted secrets before their first email. This door removes all of it. `connect.sh google` builds the consent URL (a fleet client whose consent screen is **Internal**, so Google's restricted-scope verification and annual assessment never enter the picture), catches the loopback redirect on `127.0.0.1` with an **ephemeral port**, exchanges the code, and writes the refresh token to the home's vault **by key** — never printed, never in argv (`hodd-set.sh --stdin`), proved by one `GET /users/me/profile` and reported as `account <address> · grant live · expires <t>`. `google --check` is the boot check and says `grant dead: invalid_grant` — a dead grant can never again read as an empty inbox. `connect.sh imap` is the guest road: address + app password (on stdin), validated by a **real LOGIN and a real EXAMINE**, ending in `mailbox <addr> · INBOX · <n> messages`; a wrong password fails in one line and stores nothing. `connect.sh status` gives the honesty line per account — `readable · sendable · deliverable`, where deliverable is `bin/mail/addresses.sh`'s own register and `sendable` is measured from the grant's scopes, not assumed. `connect.sh revoke <account>` is revocation as a **verb**: the vault key goes dark and the door names what stopped, per surface. Sending is deliberately absent — it stays at `systems/snotra/services/letters/mail-send.sh`, where the operator's word is bound to the exact RFC822 bytes, and a test fails if a send path appears in `bin/mail/`. Register rows are **inserted, never rewritten** (`hodd/memory/mail/accounts.yaml`), and a revoke is an append-only event in `connect-log.jsonl`. `--self-test` proves all 25 claims offline against a fixture token door, a fixture `users/me`, a fixture IMAP server and a real age vault; `--self-test` per verb reports that verb's own proofs. Measured on the day it was built: the seat's live grant carries `gmail.readonly` · `gmail.compose` · drive · docs and **no `gmail.send`, no `calendar.events`** — which is precisely why `status` refuses to call it sendable. **An app password cannot drive CalDAV** (measured: `PROPFIND` with Basic → `401 loginRequired`, no `WWW-Authenticate` challenge, while a bearer is parsed and refused differently) — so the guest road is mail-only, and a guest calendar needs OAuth | [docs/features/connect-the-mail-and-calendar-door.md](docs/features/connect-the-mail-and-calendar-door.md) |
