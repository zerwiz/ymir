| Gate | **The outbound gate — nothing leaves until you have read it** (`systems/snotra/snotra-approve.sh` · `systems/snotra/mail-send.sh` · `systems/snotra/calendar-invite.sh` · [how-to](docs/features/the-outbound-gate.md)) | Every outbound door asks one question before it acts: does the operator's approval match the bytes that would leave? Measured 2026-10-24 (plan 124 §7): the gate stood in **one** door and three walked past it — `mail-send.sh send` never checked (the gate was a caller's habit, so every other caller sent freely), `calendar-invite.sh` posted `sendUpdates=all` (Google mailed every attendee the instant an event was made), and Gná's absent send path was an unwritten debt a later hand could have filled without noticing the gate existed. Now the check is a verb of each door (`gate mail|event`), an approval is **spent** by the send it authorised (`ALREADY SENT` refuses a replay), an edit after approval reads `STALE`, every refusal and spend is carved into the Runes, the calendar defaults to `sendUpdates=none` and sets `all` only on a fresh approved event body (its `cancel --notify` too), and endpoints are configuration rather than constants (`YMIR_GMAIL_API_BASE` · `YMIR_CALENDAR_API_BASE` · `YMIR_OAUTH_TOKEN_URL`) so the gate is **proven without a mailbox**: 12 tests, no Google in the loop, each door carrying its own `--self-test`. Gná's send path stays owed to plan 116 and her own ward (`test_gna.py::NoSendCapability`) still fails if one appears | [docs/features/the-outbound-gate.md](docs/features/the-outbound-gate.md) |
