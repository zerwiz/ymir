# Ymir in Codex

Use the `ymir` MCP tools for the same runtime doors exposed by Ymir's OpenCode plugin. Recall before acting and record lessons afterward. The adjacent `../../runtime.json` in an installed plugin records `root`, the canonical Ymir code directory. Read that root's AGENTS.md and the owning Galdr asset before changing a governed surface; do not assume the current chat directory or plugin cache is the Ymir checkout. The installer supplies the code root; the private home comes from the canonical resolver, never the chat workspace.

`ymir_errand` dispatches through the canonical spawn gate. `subagent` reads the canonical figure roster and uses `eindri-dispatch.sh --figure`, requiring an explicit definition of done and seat choice. Preserve the brief, delivery contract, Yggdrasil isolation, approval and merge gates. `subagents` lists figures and `gna_watch_arm` requests the existing watcher door. Pi native panes, shortcuts and UI remain Pi-specific.

Home writes refuse traversal, escaping symlinks, credential paths and overwrite. Notes and daily logs append. New plans require the selected `YMIR_REALM`, explicit project and a complete plan body. The canonical plan audit must pass before the plan and its status index row are written. Placement copies by default and moves only when requested. Import defaults to preview. Name individual files when committing. Set `YMIR_REALM` to search one realm's content; no tool chooses a private realm on your behalf.

The existing Codex project hooks and canonical skill/agent bindings remain owned by Ymir's harness installer. This plugin does not register duplicate hooks. Shell doors require the supported Bash runtime and dependencies; missing dependencies return errors. From the canonical Ymir code root, use `node bin/seat/codex-plugin-install.mjs` to install or refresh, then start a new Codex chat to reload the installed plugin.
